# 分玩家语音（实验性 · 仅 Linux · 默认关闭）

把 VRChat 里**每位玩家**的语音单独解出来，一人一条音轨，之后可以按人翻译、按人上屏。

> **这不是给主线用户的功能。** 它要读游戏进程内存，属于 VRChat ToS 的灰区，
> 作者**不保证账号安全**。请先用小号验证；公开世界里采集他人语音还需自行取得同意。
> 主线的「别人说话」那条腿仍然抓 VRChat 的混音输出，行为不变。

---

## 一、为什么难

VRChat 把所有玩家的语音混成一路播放，操作系统层面**没有**逐玩家通道。但它在网络上
本来是**按玩家分别发送**的（Photon `Event 1` / USpeak），只是到了客户端才混音。
所以唯一的精确拆法是在**协议层**把包按 `actor` 拆开 —— 前提是能拿到那把 32 字节的
会话密钥（客户端本地随机生成，只存在于游戏内存里）。

| 路线 | 能绑姓名 | 代价 |
|---|---|---|
| 音频回环 + 声纹分离 | ❌ 只能分「几个声音」 | 零风险，但重叠说话即崩 |
| **网络层旁路解密（本方案）** | ✅ 能绑 `usr_` / displayName | 要读游戏内存 |
| 房间模式（已有功能） | ✅ 对方也装 VLT 时 | 零风险，但只覆盖自己人 |

## 二、和 Windows 方案（VRCS）的关键差异

Windows 上 EAC 有内核驱动，`ReadProcessMemory` 直接被拒；VRCS 只好把游戏内存页
换出到 `pagefile.sys` 再扫盘，代价是「关内存压缩 + 重启 + 管理员 + 仅 IPv4」。
抓包侧它不是虚拟网卡，而是 `AF_INET SOCK_RAW` + `SIO_RCVALL`（`RCVALL_IPLEVEL`，
**不开混杂**），再用 `GetExtendedUdpTable` 按进程找出 VRChat 的本地 UDP 端口
（远端仍只认 `27002`）。

Linux 上 EAC 是**用户态** `.so`，没有内核组件能拦别的进程的系统调用。因此：

| 环节 | Windows（VRCS） | Linux（本方案） |
|---|---|---|
| 抓包 | `SOCK_RAW` + `SIO_RCVALL`（IPLEVEL，不开混杂）+ 按进程枚举 UDP 端口 | `AF_PACKET` + 内核 BPF（只要 `CAP_NET_RAW`） |
| 取密钥 | 扫 pagefile（要先关内存压缩并重启） | `process_vm_readv` 直接扫匿名堆（几秒） |
| 提权 | UAC 提权（管理员）+ 内存压缩管理 | **一次性** pkexec 助手（预热/取钥各一次），用完即退 |

**唯一的硬约束**：EAC 一旦切到 Linux v2（systemd 单元 + eBPF LSM + `lockdown=integrity`），
内核会**直接拒绝**外部读内存 —— 那时这条路不是「变危险」，是「没了」。所以
`vlt/players/guard.py` 会先做静态闸门判定，命中就拒绝启动。

## 三、怎么跑

### 0. 装可选依赖（只需一次）

```bash
uv pip install --python .venv/bin/python -r requirements-players.txt
```

（仓库统一用 uv；`setup.sh` 走的是同一条路径。没有 uv 时退化为
`.venv/bin/python -m pip install -r requirements-players.txt`。）

### 1. P0-a：环境姿态（零风险、不提权）

```bash
.venv/bin/python scripts/probe_player_audio.py env --json out/p0a.json
```

要看的三个数：能不能找到宿主进程、它的**匿名 rw 大小**（决定扫描时长）、
`TracerPid` 是不是 0。闸门结论 `legacy` = 可以继续；`blocked` = 这条路在这台机器上没戏。

### 2. P0-b：取钥 + 抓包 + 解码

先启动 VRChat 并**进入有别人说话的世界**，然后：

```bash
.venv/bin/python scripts/probe_player_audio.py run --seconds 90
```

- 会弹**一次** polkit 密码（提权助手的生命周期只有几秒到两分钟）；
- 前 8 秒只抓样本，之后扫内存找候选密钥，用真实报文做 GCM 认证；
- 命中后开始实时解码，`--seconds` 秒后收尾；
- 期间请让**两个不同的人各说几句**（中间留 2 秒停顿），便于确认分轨。

产物（默认 `out/players-p0/`）：

| 文件 | 说明 |
|---|---|
| `report.json` | 姿态、扫描统计、密钥**指纹**、事件直方图、每位玩家的帧数 |
| `cap.pcap` | 抓到的密文帧（可离线复现） |
| `player_actor<N>.wav` | 每位玩家的 16 kHz 单声道人声（**他人语音，用完请删**） |

退出码：`0` 成功 / `10` 被闸门拦 / `20` 没找到游戏 / `21` 助手失败 /
`22` 没抓到包 / `23` 没找到密钥 / `24` 有密钥但没解出语音 / `25` 读内存被拒。

### 3. 抓不到包时：先诊断，再猜

`run` 在「一个加密包都没有」时会自动做一次 **3 秒无过滤采样**并打印直方图。
也可以单独跑：

```bash
.venv/bin/python scripts/probe_player_audio.py sniff --seconds 5 --json out/sniff.json
```

输出长这样（示例）：

```
[diag] 收到 1204 帧
  链路层：{'eth:0x0800': 1180, 'raw-ip': 24}
  协议  ：{'udp': 1120, 'tcp': 84}
  端口 top：[['5000->27002', 20], ...]
  与端口 27002 相关的包：20
```

判读：

| 直方图 | 含义 | 下一步 |
|---|---|---|
| `frames == 0` | 一个帧都没收到 | 先确认游戏真的在联机；再看是不是抓包 socket 没收到（权限/接口） |
| `raw-ip` 有值 | 流量在 tun/加速器上，**没有以太网头** | 已支持（过滤器和解析器都按双布局处理） |
| 有 UDP 但 `27002` 为 0 | 端口不对 | 看端口表：VRChat 可能换了端口，或流量走了代理 |
| `27002` 有命中 | 抓包没问题 | 问题在密钥/解析那一步，看 `report.json` |

### 3.6 预热：没开始翻译也抓包、只记名字

名字（Event 42/253/255 的 `actor → usr_id → displayName`）只在「加入 / 属性变更」时
广播一次。以前抓包要等点「开始翻译」—— 那之前进世界，整张名单就永久错过了，只能靠
`output_log` 兜底（没有 actor 号）。

现在（`players.prewarm: auto`）：

1. 程序启动后轮询 `/proc`（2 秒一次，没游戏时零开销）；**检测到 VRChat 进程**才
   弹**一次** pkexec 授权 —— 同一个短命助手内完成「开 `AF_PACKET` socket → 采样 →
   扫内存取钥 → 交回 socket 与候选 → 退出」（不是开抓包、扫内存各弹一次）；
2. 只有游戏重启 / 密钥失效后的**重扫**才可能再弹一次（polkit 通常有缓存）；
3. 之后**持续解密并只解析玩家名**（不解码 opus、不建翻译会话，CPU 接近零）；
4. 点「开始翻译」时直接**借用** socket + 密钥 + 名字表 —— 不重新授权、不再扫
   8.8 GiB 内存（省 ~11 秒），取钥前的包也会补解一遍；
5. **停止翻译后继续预热**：socket 不关、密钥保留，名字继续更新。只有连续 10 个
   加密包都解不开（游戏重启/换号）时才自动重扫（名字表保留）。
6. **设置页状态实时**：翻译进行中由翻译腿提供计数（预热线程此时暂停读包）；
   停止时腿把自己的名字表交还预热器，状态页不会突然掉回 0 人。

| 配置 | 默认 | 说明 |
|---|---|---|
| `players.prewarm` | `off` | `off` / `auto`（检测到游戏就预热） |
| `players.prewarm_buffer_mb` | `16` | 预热期保留多少密文，供开始翻译时回放最近 5 秒语音 |

> ⚠️ 代价与边界（必须知道）：
> - 每个游戏进程**多一次**内存扫描（点开始翻译时不再扫，净次数基本持平）；
> - 检测到游戏时**只弹一次**授权（抓包 + 取钥合并）；重扫时可能再弹；
> - raw socket 从「翻译期间」变成「程序运行期间」常驻（纯被动收包）；
> - 用户拒绝授权 → 状态栏「预热不可用：未授权」，不反复弹；设置页有「重新授权」；
> - 日志只记**数量**（`已识别 N 位玩家`），不逐条打印名字。

界面：`⚙ 设置 → 分玩家` 一页管全部参数（模式 / 预热 / 名额 / 静音门限 / 滞回 /
距离 / 高级 / 状态 + 重新授权）。改动即时写入 `config.yaml`；`mode` 与 `prewarm`
立即生效，其余参数在**停止并重新开始翻译**后生效。

### 4. 在界面里用（可见「谁说的 / 原文 / 译文」）

在 `config.yaml` 里打开（默认 `off`）：

```yaml
players:
  mode: decrypt        # off | decrypt
  max_sessions: 4          # 同时最多几条翻译会话（决定「多少人能逐人翻译」；可调到 8）
  gate_db: -55.0           # 每人流的静音门限（RMS）
  gate_hysteresis_db: 6.0  # 开闸后要再低这么多才关闸（治轻声/断续被切成多轮）
  pre_seconds: 120.0   # 等加密流量的最长秒数
```

打开后点「开始翻译」，方向选**「别人说」或「双向同时」**：

- 「别人说」那条**混音腿会被自动替换**（不并存，避免一句话翻两遍 / 双倍烧配额）；
- 说话者的名字、原文、译文会进**聊天区**，并镜像到**手腕屏 / 桌面字幕**
  （`peer:<actor>` 稳定配色 + 昵称小字 + 原文小字 + 译文大字，这是现有渲染）；
- 同时只给最多 `max_sessions` 个人建会话；名额满时只回收 **>15s 没说话**的人，
  全都在说话就丢弃后来者并警告（不混音、不踢正在说话的人，见 3.5 ④）；
- 名字、密钥状态、扫内存进度都会打到状态栏/日志（禁静默降级）。

> ⚠️ 第一次开始会弹一次 pkexec 密码（提权助手开抓包 socket + 扫内存）。
> EAC Linux v2 迹象命中时闸门会直接拒绝并在状态栏说明原因。

### 3.5 抓包与取钥的三个补强（对齐 VRCS 的做法）

这三条不改变协议假设（还是 `udp 27002` + Photon + USpeak/Opus），只提高「抓到的
包有多少真正变成字幕」。

#### ① 取钥期间的包不丢：缓冲 + 回放

扫内存要几秒到十几秒。这期间的包原来只会留在内核缓冲里，溢出就永久没了 ——
丢掉的恰好是最值钱的一段：加入世界时那批 Event 255 玩家名单，和开头几十秒的语音。

现在 / 取钥期间由 `vlt/players/pending.py` 在用户态缓存：

| 缓冲 | 上限 | 作用 |
|---|---|---|
| 主缓冲 | 4096 包 / 16 MiB | 最近的流量；世界加载完成后按 10s TTL 修剪 |
| 启动前缀 | 512 包 / 2 MiB | 被主缓冲挤出去的包转存，专保那批大快照 |

密钥命中后按**时间序**回放（同一份密文只喂一次，多网卡/加速器会重复交包）。
状态栏会写「补回取钥期间的 N 个包：名字 X 人…」，`report.replay` 记下总量。

扫内存本身挪到了后台线程，主线程继续读 socket —— 否则缓存再大也接不住。

#### ② 世界闸门 + 换世界清表

`vlt/players/world.py` 跟一份最新的 `output_log_*.txt`，只认这几句：

| 标记 | 含义 |
|---|---|
| `Memory Usage: after world loaded` / `[Behaviour] Finished entering world` | 已加载，可以取钥 |
| `[Behaviour] Entering Room:` / `Joining wrld_` / `OnLeftRoom` | 加载中/已离开 |

- **正在加载就等**（最多 25 秒），不在白扫内存上烧十几秒；
- **读不到日志不拦人**：状态栏说明「世界状态未知，直接取钥」然后照常跑；
- 出向的**事件 226** 里能解出 `wrld_` ID（`photon.joined_world`）：换世界时立刻清掉
  `actor → 名字` 表、未完成分片和每人的 USpeak 序号 —— actor 号会被复用，不清必然串名。
  状态栏的「换世界 N」就是它。

日志目录默认自动找（`names.default_log_dir()`：Linux 原生 `~/.local/share/VRChat/VRChat`，
以及 Proton / Flatpak 的 `compatdata/438100` 路径）。原来 GUI 侧根本不传这个参数，
等于一条日志都没读；现在名字兜底和世界闸门都能用上。

#### ③ 按进程识别 UDP 端点（方向归属）

`procfs.udp_ports(pid)` 走 `/proc/<pid>/fd` 的 `socket:[inode]` ↔ `/proc/net/udp`，
拿到**游戏自己绑的本地端口**，再判方向：

- `src` 是 27002、`dst` 在游戏端口里 ⇒ `in`（别人的声音）；
- 反过来 ⇒ `out`（自己的声音，只用于验钥）；
- 两端都是 27002（本机恰好绑到 27002、或自环）⇒ **不猜**，直接丢。

好处是「同机别的进程连 27002 的流量」不会混进来，VRChat 重连换本地端口也能跟上
（每 2 秒刷新一次）。读不到 `/proc/net/udp` 时退回只比端口，行为和以前一致。

#### ④ 建连节奏与名额：不踢正在说话的人

**修复前的两个现象**（2026-10 真机日志）：

1. 一个人刚开口就刷屏 `[session] 连接预算已满（4/min），等待 58s`，第一句字幕要等半分钟；
2. 6 个人同时说话时更糟：`会话 0（建连 21 / 预算排队 22）`，10 分钟只出 8 条字幕，
   90% 的语音被丢。

**根因有两个，都不在服务端**：

* 采集线程是**每 20ms 一块**调 `router.feed()`（每块一个独立协程），而
  `sessions[actor]` 要等 `await session.start()` 握手完才登记 —— 中间那 0.3~3 秒里
  每一块都看到「还没有会话」，于是各自建一条，瞬间吃光预算，还会留下没人关的连接；
* 名额满了就用 LRU **踢掉刚建好的会话**（哪怕它正在被使用），于是每条会话都活不过
  1~2 秒，谁也译不出来。

现在的做法：

| 机制 | 行为 |
|---|---|
| 幂等建连 | 采集线程只**登记愿望 + 缓冲音频**，真正的建连由**唯一**的建连循环做（同时只有一条连接在飞） |
| 排队优先 | 愿望按「最近说话时间」排序；3 秒没再说话自动作废，不占名额 |
| 名额回收 | 先回收 **>15s 没音频的空闲会话**；`order` 模式下全都在说话时，更近的新来者让最远者让位；换不了人时新人的块丢弃并按 30s 频率警告（`溢出丢弃`） |
| 句首不丢 | 排队期间保留最近 **2 秒**音频，会话一就绪立刻补发 |
| 二次确认 | 拿到预算后先确认「他最近 3 秒还说过话」，说完了就放弃这次建连（不白烧一次连接） |
| 失败退避 | 5 / 10 / 15 / 30s；半成品连接立刻关掉 |
| 断线检测 | 每 0.3s 查 `is_alive`，服务端掐线后立刻丢弃并重建 |
| 建连预算 | **9 次/分钟 + 相邻 ≥6.1s**（VRCS 实测口径） |
| 限流识别 | `Throttling` / `RateQuota` / `429` / 并发超限 → 判定会话不可用，走退避重建 |
| 空闲回收 | **45s**（低于服务端 60s 响应流超时，避免 `Response stream timeout` + 白重建） |
| 快封句 | 送音频时按峰值上报 `note_voice()`（与主线同一判据）→ 玩家句子最终版从 **3.0s → 1.1s** |
| 门限滞回 | 开闸 −55 / 关闸 −61（`gate_hysteresis_db`）：轻声的人不再被"开一下→补 600ms 静音→再开"切成多轮 |
| 首句补发 | 排队期缓存 **2s 原始音频**（门限之前），会话就绪先补发 —— 轻声的句首也在 |
| 距离 | `gate` 只在**建会话时**判一次，建好之后中途永不因距离丢块；`order` 只在换人时用 |
| 电平画像 | 会话结束时打一行 `p50/p90`（只电平，不含内容），用来判断是不是门限切太狠 |
| 轮次边界 | 快封句后**只发未终结的部分**；终版归一化去重（同一轮）；`text.*` / `audio_transcript.*` 双流只认一族 —— 治「同一段反复显示」「终版越滚越长（带上前几句）」 |

名额由 `players.max_sessions` 决定（默认 **4**，可调到 8）：**在名额内=逐人署名实时；
名额满了=先回收空闲会话；`order` 模式下如果全都在说话，更近的新人会让最远的人让位；
换不了人时后来者丢弃并警告**（不混音）。想覆盖更多人就调大它，代价是账号的
并发/建连配额。

状态栏每 10 秒那行现在长这样，能直接看出是"没人说话"还是"名额不够"：

```
会话 3/4（建连 3 / 失败 0 / 预算排队 0 / 排队 1 / 溢出丢弃 240）
```

> ⚠️ 已知边界：账号级 ~10 次/分钟是**硬顶**。分玩家腿与麦克风腿各有自己的预算，
> 所以「双向同时」时两边同时重连仍可能互相挤占；正常情况下麦克风腿只连一次，
> 影响很小。

### 5. 距离（可选）

位置来自 **Event 12** 的根节点坐标（`body[4] & 0x0F == 0x07` 时，`body[6:18]` 是三个
float32）。别人的位置是**顶层事件**；**自己的位置在出向的 `RaiseEvent op 253`**
（param 244=事件码 12、245=body）里 —— 两条路径都解，才能算出「到我」的距离。

实测标定（与 Event 14 的 float 视点对比）：

| 指标 | 结果 |
|---|---|
| 有位置的 actor | 26 个（移动中的玩家覆盖 70~100%，静坐者 ~2%） |
| 距离一致性 | 7.798 m vs 真值 7.485 m（**+0.31 m，4.2%**） |
| 误差来源 | 解的是**根节点/脚下**，不是头显；静止时 ~0.3 m 常数偏置，快速走动最坏 ~1 m |

开关（默认 `off`）：

```yaml
players:
  distance_mode: order     # off | order | gate | both
  max_distance_m: 15       # 只在 gate/both 下生效
```

- `order`：会话名额满时先回收**空闲**的人（空闲会话只在烧连接，与距离无关，新来者
  距离未知也照回收）；全都还在说话时，**只有确实更近的新来者**才让**最远的那条**
  让位（距离未知不猜，不换人）。空闲者之间仍按「最远优先、同距离按最久没说话」，
  且仍保留 1 米滞回防抖动；
- `gate`：超过 `max_distance_m` 的人**不建会话**（省钱优先，但远处贴麦说话的人会被丢）；
- 开了距离后，字幕上的名字会带距离：`阿诺owo · 8.3m`。

> ⚠️ **按块判距离是错的**（2026-10 修掉）：以前 `gate` 模式对**每个 20ms 块**判距离，
> 站在 6m 边界的人一半块被丢、一半上送 → 一句话被切成碎片；静坐玩家坐标更新很稀
> （缓存 30s），一次判远就整段不翻。现在 `gate` 只在**建会话时**判一次，
> 已建会话中途不丢块。推荐仍然用 `order`（不会因为距离在句中丢块）。

> 建议先用 `order`：它不会因为距离把某人中途丢掉，只会在名额满时按距离换人
> （被换下的那句会丢，之后要靠建连预算重建）。
>
> ⚠️ 两个前提：① **自己至少动过一次**（位置按需下发，一直站着不动可能没有本机坐标，
> 此时距离未知 → `order` 不按距离换人、空闲回收照常，`gate` 不生效）；② 别人的位置
> 静坐时更新很稀，用「最后一次已知位置」缓存 30 秒。

### 6. 玩家名

`run` 会自动：

1. 从 Photon 的 **Event 42 / 253 / 255** 里解 `actor → usr_id → displayName`：
   按 Protocol18 类型表做**结构化解析**（`0x15` map、`0x14` 字典描述符、`0x1c`
   无负载、`0x49` 数组…），按 key 取 `user.displayName` / `user.id`，与字段顺序无关；
   老的"正则 + 位置"路径保留作兜底。解不出时日志会打印**字段名序列**（不含人名）；
   
2. 名字为空（玩家隐藏）时用 `output_log_*.txt` 的 `OnPlayerJoined` 兜底；
3. 都没有就用 `usr_` 前 8 位 / `actor<N>`，**不猜配对**。

wav 命名：`player_<名字>_actor<N>.wav`；没名字的仍是 `player_actor<N>.wav`。
文件名里的 `/ \ : * ? " < > |` 会换成 `_`，中文与 emoji 保留。

> ⚠️ **记录只在「加入 / 属性变更」时广播。** 中途启动工具，只能认识之后有过
> 记录的玩家（实测某次 90 秒抓包里 12 位说话者只认出 5 个名字）。
> 想要全员名字：**先启动工具（`run` 会等待流量），再进入世界**。
> 取钥期间的那批包现在会被缓存并回放（见 3.5 ①），但**很早以前**的加入记录
> 确实没抓到 —— 换世界再回来是最快的补法。

### 7. AppImage 里怎么用

```bash
./scripts/build_appimage.sh          # 产物 dist/VRChatLiveTranslate-x86_64.AppImage
```

打包相关的三处适配（已改好）：

| 项 | 处理 |
|---|---|
| 模块收集 | `build_appimage.sh` 的 HIDDEN 里列出整个 `vlt.players` 包；`cryptography` 只在构建机装了时才作为 hidden import 收进去 |
| 提权助手 | AppImage 是 FUSE 挂载，**root 读不到挂载点**（`pkexec` 会在弹密码前就 `Permission denied`）。所以改为**一次性安装**：`<AppImage> --install-priv-helper` 用一次 `pkexec tar` 把助手装到 `/usr/local/lib/vlt-players`（root:root，0755），之后 pkexec 执行的是 root 自己的文件。需要宿主有 `python3` |
| Windows 产物 | `build_exe.py` 的 `EXCLUDE_WIN` 与 `check_platform_purity.py` 都把 `vlt.players` 列为 Linux 独占 → Windows exe 不带它 |

> 构建机没装 `cryptography` 也能打包，只是 AppImage 里开分玩家模式时会提示缺依赖
> （其它功能不受影响）。

**AppImage 里的提权方式（不需要安装）**：AppImage 是 FUSE 挂载，**root 读不到挂载点**
（`pkexec <挂载点里的程序>` 会在弹密码前就 `Permission denied`）。所以改成：

```
pkexec /usr/bin/python3 -  <参数…>        # 助手脚本经 stdin 传进去
```

- root 只执行系统自带的 `python3`；脚本内容由主程序在内存里拼好（6 个纯 stdlib 模块），
  **不落盘、不安装、不依赖挂载点可读**；
- 也避免了"把用户可写文件交给 root 执行"的本地提权面；
- 需要宿主有 `python3`（Arch 自带；缺了会明确提示）。

### 8. 离线重放（改协议假设时用）

真机每迭代一次要「开游戏 + 弹密码 + 说 90 秒」，太贵。所以可以把抓包和密钥留下，
之后**完全离线**重跑解码：

```bash
# 抓的时候顺手存密钥（0600；仅用于离线分析，用完请删）
.venv/bin/python scripts/probe_player_audio.py run --seconds 90 \
    --save-key-to out/players-p0/key.bin

# 之后改完代码，直接重放，不用游戏、不提权
.venv/bin/python scripts/probe_player_audio.py replay \
    --pcap out/players-p0/cap.pcap --key-file out/players-p0/key.bin
```

`replay` 用的是**同一套** `VoiceCollector`（解密 → 分片 → 音频 → wav），所以它能
复现线上的全部判断，只是不再有 socket。

### 9. 失败时看什么

| 现象 | 先查 |
|---|---|
| `22` 没抓到包 | 先跑上面的 `sniff`；也可 `--loose-filter` 放宽到「全部 UDP」试一次 |
| `23` 没找到密钥 | `report.json` 的 `needle_hits`：为 0 说明 needle 假设不成立；很大但验不过说明布局/密钥不对 |
| `24` 有密钥没语音 | 看 `report.json` 的 `fragments`（丢了多少分片）、`events`、`audio_param_hits`（哪个消息码里出现音频）、`payload_samples`（每个码前 48 字节）与 `first_voice_body_hex` |

## 四、安全边界（这是承诺，不是愿望）

- **只读**：不存在写目标内存的代码路径（`tests/test_players_safety.py` 用 AST 钉住）。
- **不 attach**：不用 `ptrace`/`gdb`/`gcore` —— 那会让目标进程 `TracerPid` 变成非 0，
  而那是 EAC 类模块明确会读的字段。
- **不留 fd**：不用 `/proc/<pid>/mem`（打开会留下可枚举的符号链接）；只用
  `process_vm_readv`，一次系统调用，目标侧无痕迹。
- **不提权常驻**：助手由 pkexec 拉起，只做「开包 socket + 扫候选」两件事，把候选交回
  后退出；主程序永远拿不到原始内存。不给解释器加 `setcap`。
- **不落盘敏感物**：密钥只在内存里，日志只出现 sha256 前 8 位指纹；pcap 里只有密文。

**仍然存在的风险**：EAC 是闭源且会更新；这条路属于 ToS 灰区，判定权在 VRChat。
技术上能做的只是「把可观测痕迹压到同类工具的最低档」，不能保证不封号。

## 五、已知限制

- 仅 Linux（Windows 侧有 VRCS 那套，本仓库不做）。
- 仅 IPv4 / UDP 27002（VRChat 的实测行为）；`ihl != 5` 会被统计并提示。
- 抓包同时支持**以太网帧**与**裸 IP 帧**（tun / 加速器 / 部分 VPN），内核 BPF
  两种布局都认；不指定网卡时不 `bind`（空接口名会让 CPython 走到 `ENODEV`）。
- 密钥在**同一次游戏进程**内跨世界复用；VRChat 重启后需要重新授权（再弹一次密码）。
- 与主线「混音腿」**互斥**：分玩家模式可用时替换掉混音腿，失败时回落并告警（P2 接入）。
- 密钥扫描会**全量**覆盖可写映射（实测约 8.3 GB，约 11 秒）；候选不设小上限
  （P0-b 踩过：上限 4096 让扫描在 2.75 GiB 处提前结束，真钥在后半段）。
- 自动尝试两种长度字段布局（`<u64 32>` / `<u32 32>`）与三种 AAD 布局
  （19 字节 / 7 字节 / 空），命中时报告用的是哪一种。
- **不依赖事件码**：P0-b 实测真实流量里连一个 `Event 1` 都没有，音频出现在别的
  消息码上；判据是「参数 245 存在且能切出合法 opus 帧」（由 libopus 自校验）。
- 音频长度前缀依次尝试 LEB128 / u16 LE / u16 BE / u32 LE（实测 u16 LE 命中）。
- 分片按 **(channel, startSeq)** 并发装配（上限 64）；同一 channel 上多条消息
  交错到达也能各自拼回——旧实现每 channel 只有一个槽，会把语音帧成片丢掉。
- 名字来自 Event 42/253/255；**中途启动只能拿到部分人**（详见「玩家名」一节）。
- 实测 actor 号在 1300~1500 区间，不是 1~255；`254`（leave）会清表，防 actor 复用串名。
- **语音的实际位置（P0-b 实测，2026-10）**：在 `Event 1`（USpeak）里，但包走的是
  **不可靠通道**（Photon command type 11/17），其 payload 在 `F3` 消息前多 4 字节。
  只按 `payload[0] == 0xF3` 判断会把**整类语音静默丢掉**——现象恰是"解密全通、
  一个语音帧也没有"。解析器现在会在前 12 字节内找 `F3` 对齐。
- 序号缺口默认**不补静音**：实测 90 秒里 6194 帧的真实人声，若把缺口补齐会变成
  19148 帧（383 秒）——那些缺口是 VRChat 自己的 VAD 停顿，不是丢包。
  需要严格时间轴时再加 `--fill-gaps`。
- 每条会话独立计费；同时说话的玩家越多，云端建连排队越久（实测配额约 10 次/分钟）。
