## 2. 踩到的四个真问题（都已定位，写代码时必须避开）

### ① `session.update` 必须带 `translation`，服务端不做字段合并
只发 `output_modalities` / `audio` / `input_audio_transcription` / `voice` 任意单项 → 一律报
`{"code":"invalid_value","message":"Invalid translation parameter."}`。
**必须整体下发**，且每次都要带 `translation.language`。

### ② 音色必须显式指定：默认音色 `Chelsie` 不被支持
不指定 `voice` 时会抛 `1011 InternalError.Algo.InvalidParameter: Voice 'Chelsie' is not supported.`（即使 `output_modalities=["text"]` 也会校验）。
**实测可用：`Tina`**（官方文档口径的默认音色）。→ 配置里 `voice` 必须有确定默认值，不能留空。

### ③ RPM 10 咬得很快，且 **每次 WS 连接 = 一次请求**
连环建连探测时立刻撞：`1007 Requests rate limit exceeded, please try again later.`
→ 设计约束：**两条常驻会话没问题，但重连必须指数退避**；测试脚本也要自带节流（本次探测曾一次性建 16 个连接，直接撞墙）。
建议：单分钟新建连接数 ≤ 4，重连退避 2s→30s 封顶。

### ④ 最初那句 `Workspace access denied` 是载荷问题，不是域名问题
第一版探针带了 `audio.input.turn_detection` + `input_audio_transcription` 组合，被 1007 顶回；
模块化探测证明**握手本身完全正常**（3.8/3.5 都能 `session.created`）。
→ 教训：**报错信息不等于报错原因**，要按字段二分定位。

## 3. 事件流实测（3.8，纯文本模式）

```
session.created → session.updated
input_audio_buffer.speech_started → response.created → response.output_item.added
→ response.content_part.added → response.text.delta ×14 → response.text.done
→ response.content_part.done → response.output_item.done → input_audio_buffer.speech_stopped
→ conversation.item.input_audio_transcription.delta ×7
→ conversation.item.input_audio_transcription.completed → response.done
```

**文本+音频模式**（`output_modalities=["text","audio"]`）：
```
response.audio_transcript.delta ×14   ← 译文文本（注意不是 response.text.delta）
response.audio.delta ×25              ← Base64 音频分片
+ response.audio_transcript.done / response.audio.done / response.done
```

**验证了审核的核心判断**：3.8 纯文本用 `response.text.delta`，文本+音频用 `response.audio_transcript.delta`，
与 3.5 的 `response.text.text`（含 `stash`）确实不同。**按代次分派事件是必须的。**

**意外收获**：即使没有显式配置 `input_audio_transcription`，3.8 也会返回源语言识别事件
（`conversation.item.input_audio_transcription.delta/.completed`）——**「原文 + 译文」双行显示可以白拿**，
手腕屏上同时显示对方原话与译文不需要额外成本。

## 4. 对设计的直接影响

1. **不再需要外挂 TTS**：`response.audio.delta` 直出译音（24kHz PCM），写虚拟声卡前做 24k→48k 重采样即可。
2. **节流器参数可用**：首增量 ~1s → 首条立即发；后续按 2s 快照，句末 flush。实测 `response.done` 在 6.5–7.6s，
   对 8.56s 语句来说相当于「说完即出完」。
3. **配置项增加两个必填默认值**：`voice: Tina`、`translation.language`（每次 update 必带）。
4. **连接预算要进代码**：`session/reconnect.py` 必须实现退避 + 分钟级新建计数，否则撞 RPM 10。
5. 旧域名可用 → **WorkspaceId 不阻塞开发**，仅在后续迁移到 `maas` 域名时才需要。
