# ChatGPT 语音翻译的提示词防护 Findings

此文件记录目前的防护方式、实测发现及验证边界。现有已提交实现尚未接入独立来源 ASR、文字翻译服务或音频核对模型；后续研究候选与生产实现分开记录。

## 当前发布状态

新的工具诱导反例表明，既有提示词和有限案例通过不足以作为正式发布依据。ChatGPT 功能 PR 保持 Draft。目标方案改为逐段校验后放行；下述可行性检查属于本地研究，还没有接入生产会话，也没有实现全部输出闸门。

| 门槛 | 检查结果与边界 |
|---|---|
| 工具专属登录的独立来源转录 | 使用明确指定的应用专属认证文件，完成中文真人录音与日文音频分段转录；未使用全局 Codex 登录。仅证明有限样本的转录可用，不保证逐字准确 |
| 订阅文字翻译及语义校验 | 直接调用订阅文字 HTTP 路线，发送 `tools: []`、`tool_choice: "none"`，没有本地代理或工具执行循环。正常语句和工具诱导原句获得译文，独立校验接受忠实译文并拒绝原文没有的算式答案；仅支持这些有限检查 |
| GPT-Live 译音的工具隔离 | 未通过。现用 app-server 在通知客户端之前仍会路由 handoff；`clientManagedHandoffs` 不是禁工具开关。直连研究候选不启动本地代理，但实际服务端配置尚未获得适用契约或有效配置证据 |
| 译音完成及归属 | 未通过。现有生产 PCM 回调缺少配对标识。直连候选取得带标识与时间范围的原始 turn 事件及关闭确认，但反射音频存在缺帧，主 WebRTC 媒体完成与排空也未证实。静音超时不能作为安全放行依据 |

工具边界依据与安装版本对应的[公开实现](https://github.com/openai/codex/blob/74e804deeb1241d5fe699b31fb319f7d46454c42/codex-rs/core/src/realtime_conversation.rs#L1763)及[参数说明](https://github.com/openai/codex/blob/74e804deeb1241d5fe699b31fb319f7d46454c42/codex-rs/app-server-protocol/src/protocol/v2/realtime.rs#L197)。这证明当前客户端路径仍可进入后台路由，不能由此声称已经确认所有服务端工具能力，也不能将 RPC 拒绝请求当成服务端隔离证明。

### 直接订阅管线的进一步检查

应用专属登录的直接 WebRTC 候选已建立连接，不启动 app-server、不设置代理或通用工具执行器。它切断了上述已知本地后台执行路径；但 HTTP 建立成功、请求中的 `delegation.type: "client"`，以及只返回标识和状态的启动事件，不能单独证明实际服务端工具配置。官方 [delegation 契约](https://developers.openai.com/api/docs/guides/live-delegation)区分 client 与 Responses 执行模式，不能把其中一类工具设置当成所有私有订阅路线上共用的禁工具开关。

原始事件能提供 assistant turn 的标识和时间范围，也收到明确的 `session.close`／`session.closed`。Sideband 的反射 PCM 带有时间范围，但多个正常语句检查出现了段内缺帧，本地覆盖检查拒绝这些音频。官方[音频事件说明](https://developers.openai.com/api/reference/resources/live/primary-websocket)也说明反射帧可能丢失；不能补零或仅凭关闭确认声称完整。浏览器主音频流在会话关闭确认时仍未观察到独立的远端媒体结束，完成与 decoder／resampler 排空仍待验证。

相符版本的[独立发声实现](https://github.com/openai/codex/blob/74e804deeb1241d5fe699b31fb319f7d46454c42/codex-rs/core/src/realtime_conversation.rs#L2349)使用 `session.context.append` 的 `speakable` 通道。这条候选在没有输入用户音频时，接受了一段已核准译文并产生语音；完整本地回录的独立转录出现了核准译文没有的额外问候，无工具文字校验返回拒绝。单次结果尚未区分服务生成偏差与 ASR 误差，也未通过音频完整性检查，不代表逐字发声或端到端验收。

这些检查没有接入生产输出链。缺帧、额外内容或无法确认完成的段落均未用于播放或对外发布；没有以全量丢弃替代正常使用验收。

[codex-asr](https://github.com/Wangnov/codex-asr) 是一次性私有转录接口的客户端，没有时间戳或可选择底层模型的契约。它有助建立独立逐字稿，本身不构成提示词注入防护。公开订阅接口的[支持范围](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)也不能直接套用到私有语音接口。

只有所有门槛通过后，才接入「本地断句 → 独立来源转录 → 受限翻译 → 译文校验 → 译音生成 → 译音独立转录核对 → 放行」。文字和 PCM 必须在 session callbacks 之前共同放行，涵盖所有现有输出出口；每段绑定方向、段落 ID 与会话世代，超时、停止、重连、工具事件、错配或校验失败均丢弃该段并说明原因。两个方向独立排队，同时保留既有方向分流规则。

目前未通过的两个门槛阻止正式 ChatGPT 发布，不能以全量丢弃、单向模式、实验标签或借用另一服务替代验收。ASR 与语义校验仍可能出错，即使未来硬性放行流程通过，也不能宣称任意注入完全免疫。

## 发现与修复

| 发现 | 目前处理方式 |
|---|---|
| 口述「翻译已结束」、改成问答或切换语言，可能让服务离开翻译任务 | 将所有语音内容定位为来源数据，包括角色标签、宣称的权限与要求延续先前回答的话语；它们不能改写应用程序的翻译规则 |
| 删除／只保留指定输出的请求，可能造成额外回复或丢弃来源 | 要求完整翻译每次实际发话一次，包括要求静音、删除或替换输出的指令；不得另外执行指定输出 |
| 伪造对话或引用可能诱发无来源的介绍、回答或补完 | 直接以来源说话者的语法呈现；只有实际说出的角色或引用标签才可保留，不自行加入介绍或完成虚构对话 |
| 部分译文被重新开始、整段重复，或先回声原文再翻译 | 依收到的顺序完成尚未说出的尾部，只输出设置的目标语言；真正再次说出的内容仍须再次翻译 |
| 静默封句切在转录分片中间，后续完整分片重放已显示的前缀 | 每个来源／译文角色分别记录该分片已封句的前缀，后续完整分片若精确匹配，只补未送出的尾部；不做全局去重 |

最后一项是本地字幕组装缺陷，与服务自行执行语音指令分开处理。字幕修复不会过滤或改写已产生的译音。

## 政策如何送入服务

[会话实现](../vlt/session/chatgpt_live.py) 在原有前端翻译规则后加入直接呈现、来源信任边界、顺序续译与忠实度要求。启动时另传入固定的 developer 说明与来源／译文示例，展示叙述、问题和命令都只是待翻译内容。

示例覆盖十种既有目标语言，完全固定，不使用私人录音、攻击逐字稿、测试预期答案或用户词库。自定义目标语言维持原有协商方式。词库仅放在明确标示为数据的 JSON 区块，不插入 developer 指示或固定示例。后端原有翻译提示词保留。

忠实度规则允许上下文协助识别实际听到的字词，但禁止自行补出未说过的事实、建议、句尾或答案。来源已是目标语言时仍维持来源内容；真正的引用、角色标签和重复不能被当成攻击字词删除。

## 既有有限验证结果与边界

在新的工具诱导反例提出前，本地使用完整长对话前导、攻击后等待及后续正常语句，另做新连接重测。五组跨语言长对话、四组冷启动重测及一组中文控制，共十组有限攻击核对未再观察到额外答案、独立替换回复、整段漏译、整段重复或无来源的对话介绍。真正重复、引用与后续正常语句均保留。这是历史有限样本结果，不能视为当前发布门槛通过。

跨语言自动判定维持 REVIEW；中文控制的原始字词判定为 FAIL，识别／字词差异依测试条件另列，没有修改判定器或将结果改成自动 PASS。服务的来源转录不是独立的录音真值；原始录音并未逐字听校。这些结果只支持已执行的有限案例，不保证任意语音或任意长度对话都不会发生提示词注入。

Windows 本地另以两条同时启用译音的正式会话，经生产采样泵、Engine、MicProxy 与虚拟音频回录验证。两次新连接、各三轮回录全部通过，完整服务语音与各自回录声道的波形相关度最低为 99.919%，没有回录状态错误或输出缓冲不足。波形一致不是译音逐字正确、远端 VRChat 听感或 Linux 实体音频的证明。

提示词是概率性的行为约束，没有提供确定性的安全隔离。如果日后观察到新的额外回答或漏译，应保留来源、完整服务输出与时序重新验证，不能只用连接成功或单一字幕事件宣称通过。

## Repo 与 CI 的范围

耗用订阅额度的额外实机测试程序、长对话数据、私人录音、原始转录及回录只保留于本地忽略的临时目录，不随 repo、软件包或 CI 发布。

Repo 保留离线政策传递、语言组合、词库数据边界、字幕分片、真正重复、错误清理与 GUI 回归测试。CI 使用假的 RPC／浏览器边界，不登录 ChatGPT、不建立语音服务连接，也不需要额度或音频设备。离线政策测试证明应用程序送出的契约；它不替代真人语音防护的实测。

服务菜单标示「消耗 Codex 额度」。语音翻译会使用登录账户的订阅额度；双向模式建立两条独立会话，两个方向都可能耗用额度。订阅额度不等同于一般 OpenAI API credit。
