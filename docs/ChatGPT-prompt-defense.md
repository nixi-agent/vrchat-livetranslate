# ChatGPT 订阅语音翻译的提示词防护 Findings

本文记录 Python 订阅候选的防护方式、有限验证和已知限制。本地核心功能的收尾与发布验收分开记录；功能 PR 保持 Draft。

## 目标与方向分流

保留正式双向功能，并尽量忠实翻译每次实际发话。问题、命令、引用、角色标签、要求结束翻译或替换输出的句子，都是合法的翻译来源；出现攻击字词本身不是拒绝理由。

需要拒绝的是执行口述要求、回答原问题、添加无来源内容、改变数字或否定、漏掉重要内容的候选。不能靠全部丢弃取得通过结果。真正重复发话应逐段保留，不能按文字全局去重。

沿用现有分流：「我说」仅在实际译音输出端存在时生成译音；「对方说」只显示字幕，不发 chatbox、不播译音。房间上行仍只发布麦克风来源。双向是两个方向独立处理，不扩大任何出口的资格。

## 当前 Python 管线

**收音 → 本地断句 → 独立来源转录 → 忠实翻译 → 文字校验 → 按需生成候选译音 → 实际 PCM 封存 → 盲音频转录 → 内容校验 → 放行。**

纯字幕模式在文字校验通过后放行，不生成未使用的译音。字幕与译音模式必须等实际候选的音频校验通过，才一起放行；播放的是同一份已核准 PCM，不重新生成、裁掉失败部分或用反射音频替换。

- [会话入口](../vlt/session/chatgpt_validated.py)使用[专用订阅中转](../vlt/session/chatgpt_relay.py)，推论不启动 app-server、Codex 任务、shell、MCP 或通用工具执行器。官方 CLI 只用于应用专属登录和状态检查，不读写全局 Codex 登录。
- 凭证由单一 owner 管理。登录和更新互斥，旧账户或旧登录世代失效；凭证原子写入、权限、链接与重定向检查有离线回归。请求结果不明时不自动重送生成。
- 固定订阅目的地、模型和认证方式，拒绝重定向及任意地址，不切换另一服务或一般 API credit。文字请求禁用工具，没有代理执行循环；来源、词库和译文只作为 JSON 数据。
- 会话启动先验证专用登录并准备共享的验证 TLS context，再处理已排队的取消、关闭、账户世代及输出资格变化；这些检查通过后才建立 coordinator 并报告 ready。Windows 系统 CA 初次枚举可能阻塞 event loop，因此放在输入泵启动前；不能据此宣称已完成实机延迟验收。
- [分段器](../vlt/session/chatgpt_segments.py)处理 16 kHz 单声道 PCM，初始参数为峰值 220、500 ms 静音、最多 1 秒未分配 preroll。已结束的样本不进入下一段；超过 30 秒整段拒绝，等待下一静音边界恢复。这些参数尚未完成实机校准。
- [逐段 coordinator](../vlt/session/chatgpt_pipeline.py)为两个方向分别排队，每方向最多一段处理中、两段等待。超载、超时、旧世代、工具／handoff、错配、超限、缺少完成事件或校验失败时拒绝该段并报告受限原因。
- [直接 Live adapter](../vlt/session/chatgpt_voice.py)逐段建立独立连接，核对主事件通道与侧通道的会话及助手回合。匹配完成、主动关闭确认和正常 WebSocket 收尾之后，才 flush 本地尾样本、核对样本数 ACK 并冻结完整候选。静默或连接关闭不能单独证明完成。
- 原始事件解析有单帧和累计预算。未知、工具、handoff、额外回合或归属不符使候选失效，不执行委派。反射音频只作有界观察，不播放、补零或拼补主音频。

文字校验包含语言、结构、长度、语义、数字、否定和完整性。盲音频 ASR 只收到完整候选音频及必要语言，不取得核准译文；后续比较器再核对转录与核准译文，包括额外问候、回答、缺字和缺尾。简繁差异可以规范化比对，显示转换在校验后进行。

来源 ASR 参考固定版本的 [codex-asr 协议](https://github.com/Wangnov/codex-asr/blob/479f6a7a3db81fe2a23d4755b0ccbeb4400317d4/src/lib.rs)，由 Python 实现必要请求，不新增其执行文件。该客户端没有时间戳或可选择底层模型的契约；建立逐字稿本身不构成提示词防护。

## 放行与撤销

每段绑定方向、会话世代、候选身份、核准译文和音频哈希。核准身份仅保存在内部闭包与队列中，保留既有 `on_text`／`on_audio` 外部接口，不加入房间协议或字幕正文。

[Engine Admission](../vlt/session/chatgpt_admission.py)让同一核准结果跟随延迟消费者。停止、重连、语言、服务、方向、词库或账户变化使旧结果失效；设置改回原值也不能复活旧核准。来源及候选处理的每个远端阶段在 await 前后检查上下文，已撤销的段落不继续启动下一阶段。

已经发出的远端请求不一定能即时停止计费，已经交给设备或网络的内容也无法追回。撤销保证针对应用仍持有的结果和队列，不能扩大为设备、运行时或远端已经显示／听到的内容可撤回。

相关离线回归覆盖 Engine callbacks、GUI 消费、chatbox 延迟发送、音频软件缓冲和房间发布；overlay 与 Linux 原生消费者的剩余改动仍需完成独立验收。不能仅凭 coordinator 没有回调，宣称所有实体出口安全。

启动、重建和重连还必须区分真正建成、停止及建立权转移。未核准或被另一个重建接管的会话，不应启动采集或回报成功；这部分属于生命周期修复，不能当作模型抗注入的证明。

## 工具边界与历史路线

旧 app-server 路线会在通知客户端前路由 handoff，RPC 拒绝请求和 `clientManagedHandoffs` 不能当成禁工具证明。当前 Python 候选移除了这一已知本地执行路径；本地没有工具执行循环，任何工具／handoff 事件都拒绝。

供应端未公开的工具所有权仍未确认，保留为风险，不再以取得私有隔离契约作为继续实现和服务验证的前提。握手成功、配置 ACK、有限攻击通过或未观察到工具事件，都不能提升为完整服务端隔离证明。[公开 delegation 说明](https://developers.openai.com/api/docs/guides/live-delegation)与[公开 Sign in with ChatGPT 预览限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)不能未经验证直接套用于私有订阅路线。

提示词只是概率性约束，ASR 与语义校验也可能出错。即使硬性流程和有限攻击集全部通过，仍不能宣称任意长度、任意语言或任意注入完全免疫。

公开 Live 的 [commentary／speakable 更新](https://developers.openai.com/api/docs/guides/voice-server-controls)是供模型传达的上下文；[协议参考](https://developers.openai.com/api/reference/resources/live/fork-websocket)也没有承诺按原字逐字渲染。这些公开 API 文档未建立私有订阅路线的发声控制或授权适用性，不能直接作为新参数、原文朗读通道或保真修复的依据。原研究分页面临载入故障，未取得完整报告；这里仅记录后来直接查阅官方页面所得的有限结论。

## 本次核心收尾范围（2026-10-13）

使用者接受目前的翻译品质，明确选择「核心功能收尾，发布项目留待后续」。本次保留双向、既有方向分流与 GPT-Live 发声，完成提示词注入检查，并保留数字、否定、缺尾及输出资格的严格闸门；没有把 28／16 的有限结果改写为全通过。

针对新增的四个情境，六次订阅文字请求完成，没有重试：冒充 system 的原句按原目标语言照译，恶意词汇表没有改变任务；含伪造核准声明的错误数字与否定候选都被拒绝。59 个相关离线测试覆盖 JSON 输入隔离、禁工具与委派、角色／完成事件、固定模型和 RPC 拒绝执行。独立审查完整阅读 13 个相关 source、4 个 test，并追查必要调用路径及输出 admission，未确认本次范围内存在可利用的提示词注入、未授权操作或泄漏路径；没有已确认的 P0／P1／P2 安全阻挡项。

Windows 桌面检查与 Linux 真实 PipeWire 合成音源切换回录已有有限有效证据；后者实测原声 1000 Hz → 译音 500 Hz → 原声 1000 Hz，退出后节点消失。该环境没有可辨识的默认输出，因此默认输出前后都是 -1 的检查不能证明保留既有可听输出。

上述结果支持按使用者接受的品质完成本次核心收尾，不证明任意提示词注入免疫或所有语音逐字正确。正常句漏字、换词及 ASR 误挡仍是已知品质限制；既有失败证据保留。正式发布、最终候选 CI、Linux 桌面及头显的未验收状态不因核心收尾而改变；fork CI 另外验证，不沿用较旧提交的绿灯。

耗用订阅额度的实机程序、长对话数据、录音、原始转录和回录只保存在本地忽略目录，不进入仓库、软件包或 CI。公开 Findings 仅记录方法、有限结果和边界，不包含账户、录音、私人路径或审查者信息。

正式 CI 仅运行离线测试，使用合成 PCM 与假的服务／浏览器／设备边界，不登录 ChatGPT、不建立语音服务连接，也不要求额度。工具专属登录隔离、目的地限制、事件归属、封存、输出撤销和兼容性测试，不代替真实语音防护实测。

服务菜单标示「消耗 Codex 额度」。两个方向都可能使用登录账户的订阅额度；订阅额度不等同于一般 OpenAI API credit。
