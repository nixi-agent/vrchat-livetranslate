## 0. 最速で始める：用意された exe をダウンロード

**[Releases](https://github.com/nixi-agent/vrchat-livetranslate/releases/latest)** から
**`VRChatLiveTranslate.exe`** を入手し（**単一ファイル・インストール不要・コンソールウィンドウなし**）、
ダブルクリックするだけです。

- **Qwen Cloud の API key** はご自身で用意してください。「⚙ 設定」で貼り付けて保存します
- 設定とログは `%APPDATA%\vrchat-livetranslate` に置かれます（読み取り専用フォルダに exe を置いても動作します）
- ポータブル運用（設定を exe と同じ場所に）したい場合は、exe の隣に**空の `portable.txt`** を置きます
- 古いバージョンが exe の隣に `config.yaml` / `logs/` を残している場合、初回起動時に**自動で新しい場所へ移行**します。元のファイルは削除されません

### 自動更新されますか？

**自動で確認はしますが、勝手にインストールはしません** — 更新するかどうか、いつするかは常にあなた次第です：

- 起動のたびにバックグラウンドで一度だけ静かに確認します。確認に失敗しても（ネットワーク不通など）邪魔はせず、ログに残すだけです
- 新しいバージョンが見つかると、3 つの選択肢があるダイアログが出ます：
  - **今すぐ更新** → 自動でダウンロードします（1〜2 分程度）。完了後に「今すぐ再起動して更新」を押せばその場で切り替わり、
    「後で更新」を押せばアプリを閉じるときに差し替えられ、次回起動から新バージョンになります
  - **次回にする** → この起動中はもう表示しません。次回の起動時にまた確認します
  - **このバージョンは通知しない** → そのバージョンだけ無視します。次のバージョンでは改めて通知します
- ダウンロード失敗時は再試行できます。ウィンドウ内の「ダウンロードページを開く」から Releases に取りに行くこともできます
- ポップアップが出ていないときに確認したい → 「⚙ 設定 → ソフトウェア更新 → 更新を確認」
- 更新で**設定と API key が失われることはありません**。更新後は次回起動時にお知らせします

**ソースから実行している場合**：上記は適用されません。リポジトリで `git pull` してください
（ソース実行時に「今すぐ更新」を押しても同じ案内が出ます）。

ソースを読みたい／自分でビルドしたい／改造したい → 下の「1.」からどうぞ。

## 1. 前提条件

1. **Windows 10 / 11**（WASAPI と SteamVR を使用します）
2. **Python 3.11**（3.12 は未検証。インストール時に *Add python.exe to PATH* にチェック）— *exe を使うだけなら不要*
   <https://www.python.org/downloads/release/python-3119/>
3. **VRChat**：設定で OSC を有効化（`OSC enabled: True`）し、チャット吹き出しの表示を **Everyone** にします
4. **SteamVR** — 「相手の発話 → 手首オーバーレイ」を使う場合のみ必要
5. **Qwen Cloud の API key**（個人の実名認証で OK）

## 2. インストール（ソースから）

**`setup.bat`** をダブルクリックします（`.venv` の作成と依存関係の導入、1〜2 分程度）。

手動で行う場合：

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements-windows.txt
```

## 3. API key の設定

> 🔑 Qwen Cloud のアカウントをお持ちでない場合はこちら → **[Qwen Cloud に登録 ▸](https://www.qianwenai.com/)**

以下の順に探索し、**最初に見つかったものが使われます**：

| 優先度 | 取得元 | 設定方法 |
|---|---|---|
| 1 | GUI で保存した key | 「⚙ 設定 → API key」で貼り付けて保存（`%USERPROFILE%\.vrchat-livetranslate\api_key.txt` に保存） |
| 2 | 環境変数 | `setx DASHSCOPE_API_KEY "sk-your-key"`（**新しく開いたターミナルでのみ有効**） |
| 3 | Bailian CLI の設定 | `bl auth login --api-key "sk-your-key"`（`npm install -g bailian-cli` が必要）／`%USERPROFILE%\.bailian\config.json` を読みます |

**key を読むのはこの 3 か所だけで、プロジェクト内のファイルや `config.yaml` には書き込みません。**

> 🔒 **コミット時の安全装置**：リポジトリには認証情報スキャンが同梱されています。`install_secret_guard.bat` を
> 一度実行して pre-commit フックを入れておくと、`sk-...` / `gho_...` / `AKIA...` / `Bearer ...` などの
> ハードコードされた秘密情報を含むコミットはその場で拒否されます（スクリプト：`scripts/check_no_secrets.py`）。
> 手動での全走査：`python scripts/check_no_secrets.py --once`
> 理由：key が一度 git の履歴に入ると、ファイルを消しても残ります。履歴の書き換えが必要になる前に止めるべきです。

### 海外ユーザー向け：千問雲（海外版／Qwen Cloud）

**なぜ回線が 2 つあるのか**：既定の「千問雲」は中国国内向けで、海外からは登録できず、直結も
不安定です。海外では **千問雲（海外版／Qwen Cloud、<https://www.qwencloud.com/>）** をお使いください
—— モデルもリアルタイム API も同じ（リアルタイム同時通訳・文字入力の翻訳・読み上げも揃っています）で、
違うのは入口のアドレスとアカウント体系だけです。2 つの回線は**排他**で、同時に有効なのは画面で
選んだ片方だけです。

**開通の 3 ステップ**（いずれも <https://www.qwencloud.com/> で）：

1. **Google / GitHub / メールの確認コード**のいずれかで登録 —— **電話番号もクレジットカードも不要**
2. ログイン後、コンソールで API key（`sk-ws-` で始まる）を作成
3. 新規アカウントには無料枠が付きます（モデルごとに計算）。使い切ってからチャージすれば OK

**画面での 3 ステップ**：

1. `⚙ 設定 → 一般 → サービス回線` で「千問雲（海外版）」を選ぶ
2. 「回線設定を保存」を押す（`base_url` が
   `wss://maas.qwencloudapi.com/api-ws/v1/realtime` に書き換わります）
3. 本ページ上部の「API key」欄に key を貼り付けて保存し、**翻訳を開始し直す**

> 🔑 **2 つの回線の key は共通ではありません**：海外版と国内版はそれぞれ別ファイル
> （`api_key.txt` / `api_key_qwencloud.txt`）に保存されるので、回線を行き来しても key を入れ直す
> 必要はありません。画面の「現在の設定（回線）：…」の行も回線に追従します。
> 同じアカウントでも**key を使い回せません** —— 海外版用に別途取得してください。
> 回線を変えたあとは**翻訳を開始し直して**ください（実行中なら先に停止するよう促されます）。

> ⚠️ **古い設定は自動で移行します**：以前「Alibaba Cloud 百錬（国際版）」（ワークスペース ID と
> リージョンが必要で、海外からの登録はカード利用明細を求められることがありました）を選んでいた
> 場合、本バージョンからは起動時に自動で千問雲（海外版）へ切り替え、ログにもその旨を出します ——
> 海外版の key をもう一度入力してください。

**対応する `config.yaml` の 2 つのキー**（「回線設定を保存」で自動的に書き込まれます。手で編集する
必要はありません）：

```yaml
session:
  provider: qianwen          # 回線 id：qianwen（国内）/ qwencloud（海外版）
  base_url: wss://maas.qianwenaiapi.com/api-ws/v1/realtime
```

海外版に切り替えると `base_url` は次のようになります：

```yaml
  base_url: wss://maas.qwencloudapi.com/api-ws/v1/realtime
```

**実際にどこへ接続するかを決めるのは `base_url` だけ**です。`provider` は画面の既定値と key の
保存先を決めるだけです。両回線の 3 つのパスはまったく同じ（`/api-ws/v1/realtime`、
`/compatible-mode/v1/chat/completions`、
`/api/v1/services/aigc/multimodal-generation/generation`）なので、回線の切り替えは `base_url` の
1 か所を変えるだけで済みます。

> 🔍 **トラブルシュート**：ログの `[net] 线路=… host=…` が実際に接続しているアドレス、
> `[gui] 服务线路已保存：…` が画面が書き込んだ結果です。2 行が食い違う場合は、回線を変えたあとに
> 翻訳を開始し直していないだけです。

## 4. セルフチェック

**exe を使う場合**：起動して次の 3 点を確認してください。

1. 「⚙ 設定」で 3 つのデバイスドロップダウンが空でないこと（`マイク` / `VRChat の音声` / `翻訳音声の出力`）
2. API key の状態が**設定済み**になっていること（未設定の場合はクリックすると登録ページが開きます）
3. `chatbox` にチェックを入れ、「翻訳を開始」を押してマイクに一言話す → 吹き出しに訳文が出ること

**ソースから実行する場合**：**`run_selfcheck.bat`** をダブルクリックします。次の 4 つを順に実行し、最初の 3 つはマイクも VRChat も不要です。

1. モジュールのインポート確認（engine / session / overlay / chatbox / merger）
2. API key を一度読み、マスクして表示（優先順位の確認）
3. 手首オーバーレイの 1 フレームをオフライン描画（SteamVR を占有しません）
4. 同梱のテスト音声をパイプライン全体に通す（中国語 → 英語、chatbox へ）

VRChat が起動していれば、吹き出しに次のように表示されるはずです：

```
Hello, I'm Nixi. Today, we're going to test out the real-time simultaneous interpretation feature in VRChat.
```

**不具合を報告する前に、必ずこのセルフチェックを実行してください。**

## 5. 使い方

### GUI（推奨）

**exe をダブルクリック**、またはソース版なら **`run_gui.bat`** をダブルクリックします（どちらも同じウィンドウです）。
（Tkinter のみ使用・標準ライブラリだけで動作・追加依存ゼロ・即起動）

| エリア | 内容 |
|---|---|
| 1 行目 | `翻訳を開始` ⇄ `翻訳を停止`（**同じボタン 1 つ**：未翻訳時は青の「翻訳を開始」、翻訳中は赤の「翻訳を停止」に変わり、押すだけで切り替わります）、方向のラジオボタン（`自分` / `相手` / `双方向`）、言語ペアのドロップダウン（原文 → 訳文）、右側に `☕ サポート` と `⚙ 設定` |
| 2 行目 | `出力:` の `chatbox` / `手首オーバーレイ` / `デスクトップ字幕` / `翻訳音声を出力` チェックボックス。`chatbox` の右隣のボタンで**バブルに原文を表示するか訳文を表示するか**を切り替えられます；「翻訳音声を出力」にチェックを入れると、右側にさらに `🎙 自分の声` / `🗣 翻訳の声` ボタンが現れます（相手に何が届くかを決めるもの。詳細は「マイクプロキシ」の節を参照。仮想サウンドカードが未導入のときはグレーアウトします）；右端に API key の状態（設定済みなら `API key 設定済み`、**未設定ならクリックできる「⚠ API key 未設定 ・ Qwen Cloud の登録はこちら ▸」**）。**手首オーバーレイ / デスクトップ字幕の微調整は「⚙ 設定」の中**（`設定 → 手首オーバーレイ` / `設定 → デスクトップ字幕`） |
| チャット欄 | 右の青い吹き出し＝自分の発話、左の灰色＝相手の発話。1 つの吹き出しは 2 行構成で、**上に原文を小さく、下に訳文を大きく**表示。履歴はスクロール可（最大 500 件） |
| ステータスバー | 左：色付きの丸印＋最新の状態メッセージ／右：統計（`実行中` / `{n} 件翻訳` / `初回差分 {ms}ms`）。両者は重なりません |
| 下部バー | **テキスト入力**：`テキスト入力:` 欄と `送信`。**Enter で送信**（`Esc` でクリア）。方向に「自分」が含まれるときだけ有効で、それ以外はグレーアウトします |
| `☕ サポート` ポップアップ | Ko-fi のリンクボタンと WeChat / Alipay の QR コード（240 px に比例縮小。そのまま読み取れます） |

- **ストリーミング表示**：未確定の差分は新しい吹き出しを追加せず、**同じ吹き出しをその場で書き換え**ます
- **双方向**：1 つのウィンドウで 2 方向を翻訳します（マイク → 右側、ゲーム音声 → 左側）。2 本目は**300 ms ずらして開始**し、オーディオデバイスの取り合いを避けます。片方が失敗しても、もう片方は動き続けます
- **言語のミラーリング**：1 つのペアで両方向をカバーします。「中国語 → 英語」を選べば、相手の発話方向は自動的に「英語 → 中国語」になります。
  原文側は `自動検出` / 中国語 / 英語 / 日本語 / 韓国語 / フランス語 / ドイツ語 / スペイン語 / ロシア語 / タイ語 / イタリア語から選べます（訳文側は同じ表から「自動検出」を除いたもの）。
  原文側で `自動検出` を選ぶと、相手方向の訳文は中国語にフォールバックし、その旨がステータスバーに出ます。変更は**即時反映**され、設定に書き戻されて次回起動時も保持されます
- **設定ダイアログ**（`⚙ 設定`、タブ切り替え）：`一般`（API key の登録／削除、表示言語、VRChat OSC ポート）、`オーディオ`（3 つのオーディオデバイスドロップダウン + `再スキャン`、入力ゲート、音色）、`手首オーバーレイ`（微調整スライダー）、`デスクトップ字幕`（字幕ウィンドウのサイズ / 文字サイズ / 不透明度）、`用語集`、`ルーム`、`情報`（バージョンとログ欄 `ログを ZIP でエクスポート…`）
- **設定 → 手首オーバーレイ**：**手首オーバーレイ**（ヘッドセット内の貼り付けテクスチャ）のアンカー + 14 個のスライダー。**ドラッグで即時反映、再起動不要**。これは「設定 → デスクトップ字幕」とは**互いに影響しません**（2 系統の設定は完全に独立：片方は VR 内のメートル単位のテクスチャ、もう片方は画面上のピクセルパネル）
- **設定 → デスクトップ字幕**：VRChat のウィンドウに貼り付く字幕ウィンドウ自身の訳文の文字サイズ / 原文の文字サイズ / パネルの幅 / パネルの高さ / 不透明度 / ドラッグの解錠
  （この 2 つは**一度設定したらもう触らない**パラメータなので、メイン画面を占有しません。変更は即時反映されます）
- **テキスト入力**：話したくないときにキーボードで代用します。下部バーに入力して **Enter で送信**。訳文は音声経路と**まったく同じ**下流（チャット吹き出し／手首オーバーレイ／chatbox）を通ります。「翻訳音声を出力」をオンにすると**読み上げも行い**、訳文を TTS で合成して仮想サウンドカードへ書き込むので相手にも聞こえます（「6. 設定」の `text_input.tts` 参照）。これは**マイクの代替**なので、方向に「自分」が含まれるときだけ使えます（含まれないときは入力欄がグレーアウトします）
- **`chatbox` のオン/オフは即時反映**：翻訳中に 2 行目の `chatbox` をチェック / 解除しても、**停止して再起動する必要はありません**。チェックすると次の訳文からバブルに出て、解除すると以降は出なくなります（すでに表示中の行はそのまま残り、自然に消えます）。セッションは再構築されません。バブルに載るのは**あなたの発話**の訳文だけなので、方向に「自分」が含まれないときはチェックしても出力されず、ステータスバーにヒントが出ます（手首オーバーレイ／チャット欄は影響を受けません）

#### 自動検証（ヘッドレス・ウィンドウを開かない）

```bat
:: ソース版
.venv\Scripts\python.exe -m vlt.gui --self-test
.venv\Scripts\python.exe -m vlt.gui --self-test-dual

:: exe（コンソールウィンドウなし。結果はログに出ます — ビルドスクリプトの自己検証と同じ方法）
VRChatLiveTranslate.exe --self-test
```

成功すると `GUI_SELFTEST_OK` / `GUI_SELFTEST_DUAL_OK mine=N theirs=N` を出力し、失敗すると `..._FAIL: ...` を stderr に出して非 0 で終了します。実際の API key が必要です。

> 🪵 **クラッシュログ**：GUI は起動のたびに `logs/` 配下に `gui_<タイムスタンプ>.log` を書き出します。
> 中には**バージョン情報**（git HEAD）、Python 環境、stdout/stderr のすべて（各行に `HH:MM:SS.mmm` の
> タイムスタンプ付き）が入ります。ネイティブクラッシュ（`faulthandler`）、メインスレッドの例外、
> 子スレッドの例外、Tk コールバックの例外の 4 種類を捕捉します。クラッシュ時は**このファイルを
> メンテナーに送れば原因を特定できます** — ウィンドウが閉じると何も残りません。
> 1 ファイル 2 MB でローテーションし、合計 5 MB を超えると古いものから削除されます。「設定」から
> まとめて**秘匿処理済み**の ZIP としてエクスポートできます。

### コマンドライン（ソース版のみ）

exe はコンソールのない単一ファイル GUI なので、上記の `--self-test` 以外にコマンドライン用途はありません。CLI はソース版でのみ意味があります。

```bat
:: 自分の発話 → chatbox（実際に VRChat へ送信）
.venv\Scripts\python.exe -m vlt.app --direction mine --mic --sink chatbox

:: 相手の発話 → 手首オーバーレイ（SteamVR の起動が必要）
.venv\Scripts\python.exe -m vlt.app --direction theirs --loopback --sink overlay

:: VRChat なしで経路を検証：同梱のテスト音声を通す
.venv\Scripts\python.exe -m vlt.app --direction mine --pcm testdata\zh_test_16k.pcm --dry-run
```

両方向を同時に翻訳する → **コマンドラインウィンドウを 2 つ開きます**（または GUI の「双方向」を使えば 1 つのウィンドウで 2 セッション動きます）。
方向ごとに独立した WebSocket セッションを持つため干渉しません（レート制限は RPM 10 で十分余裕があります）。

コマンドが長くて面倒なら、用意された bat を使ってください：**`run_chatbox.bat`**（自分の発話 → 吹き出し。先にデバイス一覧を出してから開始）と
**`run_overlay.bat`**（相手の発話 → 手首オーバーレイ）。

#### すべてのパラメータ

| パラメータ | 効果 |
|---|---|
| `--direction mine/theirs` | `config.yaml` のどちらの方向を使うか |
| `--mic` / `--loopback` / `--pcm <file>` | 音声ソース：マイク／VRChat の再生出力／オフライン PCM（いずれか 1 つ。優先度は `--pcm` > `--mic` > `--loopback`） |
| `--sink chatbox/overlay/both` | 出力先（既定は `chatbox`） |
| `--list-devices` | オーディオの入出力デバイスを一覧表示して終了 |
| `--dry-run` | 実際には OSC を送らず、表示とパケットのダンプのみ |
| `--overlay-dry-run` | オーバーレイが SteamVR を占有せず、各フレームを `out/overlay_frames/` に PNG 出力 |
| `--audio-out` | 翻訳音声の出力を有効化（`config.yaml` の `output.audio.enabled` を上書き） |
| `--audio-device <name...>` | 仮想サウンドカード名のフォールバック順（`config.yaml` の既定を上書き） |
| `--no-realtime` | PCM を可能な限り高速に流す（リアルタイム制限なし。`--pcm` と併用時のみ意味があります） |
| `--settle-s <seconds>` | 音声終了後、応答を待つ秒数（既定 8） |
| `--config <path>` | 別の設定ファイルを使う |

> マイク入力は**連続で動き続けます**：`Ctrl+C` まで止まりません（時間指定のパラメータはありません）。
>
> 📌 **オーディオデバイスの指定にフラグは不要**：GUI の「⚙ 設定」で選ぶか（ドロップダウンの先頭「自動検出」が
> フォールバック順に探索します）、`config.yaml` の `capture.mic_device` / `capture.loopback_device` を直接編集します。
> 保存されるのは**デバイス名の文字列**で、インデックスではありません — インデックスは抜き差しやセッション切り替えで丸ごとずれます。
>
> ⚠️ **一覧に出るのは「有効な」デバイスだけ、同じサウンドカードは 1 回だけ**：本アプリが列挙するのは
> **WASAPI** のエンドポイント —— つまり Windows の「サウンド」設定で**有効**になっているものだけです
> （無効なものは出ません。使いたい場合は「サウンド → その他のサウンド設定」で有効にしてください）。
> そのため「同じマイクが 2〜3 行、しかもサンプルレートが違う」という状態にはなりません。
> 名前の後ろの括弧内のサンプルレートが**実際に使われる値**です（通常 48000）。
> 古い設定の名前もそのまま解決できます（同名の WASAPI エンドポイントに解決されます）。

## 6. 設定（`config.yaml`）

> 📄 **初回起動時に `config.example.yaml` から `config.yaml` が自動生成されます。**
> `config.yaml` は**あなた自身の設定**（デバイスの選択、言語の好みなど）で、gitignore されており
> **バージョン管理には入りません**。デバイス名などはマシンごとに異なり、混ざるだけだからです。
> 既定に戻したいときは削除して再起動してください。
>
> 置かれる場所：
> - **exe**：`%APPDATA%\vrchat-livetranslate\config.yaml`（`portable.txt` があるポータブル構成では exe の隣）
> - **ソース版**：リポジトリ直下の `config.yaml`
>
> 🛟 **設定が壊れても起動できなくなりません**：YAML の解析に失敗した場合、そのファイルは自動で
> `config.yaml.broken` として退避され、テンプレートから新しい設定が生成され、理由が表示されたうえで起動が続きます。

GUI で変更したもの（方向、出力チェック、言語、デバイス、手首オーバーレイの微調整）は、このファイルに**その場で書き戻されます** —
変わるのはその 1 行だけで、**コメント・空行・キーの順序はすべて保持されます**（生成された YAML は書き込み前に検証され、不正な出力は拒否されます）。

### 主要なキー

```yaml
session:
  model: qwen3.8-livetranslate-flash-realtime   # qwen3.5-* も可（イベント名は世代ごとに自動で振り分け）
  base_url: wss://dashscope.aliyuncs.com/api-ws/v1/realtime
  voice: Tina                 # ⚠️ 必ず明示。未設定だと Voice 'Chelsie' is not supported で失敗
  turn_detection: null        # 空 = サーバー既定
  final_silence_s: 3.0        # ⚠️ サーバーの増分間隔（実測最大 2.3s）より大きくすること。小さくすると文の途中で確定版が飛びます
  fast_final_silence_s: 1.1   # 早めの確定：上流も静か（誰も話していない）なら、この文字無音で確定（約 1.8s 短縮）。null = 無効
  fast_final_user_quiet_s: 0.5  # 「誰も話していない」の判定は**レベル**。環境ノイズが閾値を超え続けると上の 3.0s に退化する
  max_new_sessions_per_minute: 4   # RPM 10 の予算：WS 接続 1 回でリクエスト 1 回と数えます
  reconnect_backoff: [2, 5, 10, 30]

capture:                      # 空文字列 = 自動検出
  mic_device: ""
  loopback_device: ""

directions:
  mine:   { source_lang: zh,   target_lang: en, output_audio: false }   # 自分 → 吹き出し
  theirs: { source_lang: null, target_lang: zh, output_audio: false }   # 相手 → 手首オーバーレイ（null = 自動判定）

chatbox:
  interval_s: 2.0             # 増分の更新間隔（漏れバケツ 5 件/5 秒 → 2 秒に 1 件なら余裕あり）
  max_chars: 144              # 公式上限（バイトではなく文字数）

text_input:                   # テキスト入力（下部の入力欄、Enter で送信）
  enabled: true               # false = 入力行を表示しない
  model: qwen-mt-flash        # タイピング翻訳は**テキスト**モデル。qwen-mt-plus も可
                              # ⚠️ qwen3-livetranslate-flash は不可：実測でテキスト入力に対して原文をそのまま返します
  timeout_s: 20               # 1 回の翻訳のタイムアウト（秒）
  tts:                        # タイピングでも読み上げる（訳文を TTS で合成 → 仮想サウンドカード → 相手に聞こえる）
    enabled: true             # 「翻訳音声を出力」がオンで、方向に「自分」が含まれる必要があります。オフならこの段は自動でスキップされ、テキストのみ
    model: qwen3-tts-flash    # qwen3-tts-instruct-flash も可
    voice: Cherry             # 多言語音色（中／英／日で読み上げ可能なことを実測済み）
    timeout_s: 30

merger:
  interval_s: 2.0             # 最初の差分は即時、以降 2 秒ごとにスナップショット、文末では必ず確定版
  carry_over: false           # true = 直前の確定訳文を接頭辞として残す（連続字幕の見え方）

overlay:
  interval_s: 0               # 0 = 更新があれば即座に表示（ローカル表示は chatbox のレート制限を受けません）
  anchor: right_hand          # left_hand | right_hand | tracker | hmd
  size_px: [1024, 320]
  font_size: 42               # 訳文の文字サイズ
  source_font_size: 30        # 原文の文字サイズ
  show_source: true           # 2 行表示（3.8 は既定で原文の認識結果も返すため追加コストなし）

output:
  audio:
    enabled: false            # 翻訳音声の総スイッチ：directions.<X>.output_audio との AND
    device_name: ""           # 手動指定の仮想サウンドカード名（空でなければフォールバック順より優先）

ui:                           # 界面上の前回の選択（画面で変えた内容がそのまま書かれます。通常は手で編集不要）
  direction: mine             # mine=自分の発話 | theirs=相手の発話 | dual=双方向同時
  chatbox: true               # 出力チェック：chatbox のバブル
  chatbox_text: translated    # バブルに表示する内容：translated=訳文（既定）| source=原文（ASR の認識結果）
                              # 画面の入口：2 行目の chatbox の右にある「🌐 バブル: 訳文 / 📝 バブル: 原文」ボタン
  overlay: true               # 出力チェック：手首オーバーレイ
  desktop_overlay: true       # 出力チェック：デスクトップ字幕
```

### マイクプロキシ：自分の声 / 翻訳音声をワンクリックで切替（既定で有効）

以前は、相手に翻訳音声を届けるには、自分で VRChat 側のマイクを仮想サウンドカードに切り替え、不要になったらまた元に戻す必要がありました。
いまはプログラムがこの仮想サウンドカードを代わりに占有するので、VRChat 側では**一度選ぶだけ**で済みます
（Windows なら導入したもの、例えば `CABLE Input` / `VoiceMeeter Input`）。あとはメイン画面で切り替えるだけです：

- **メイン画面 2 行目のボタン**（`翻訳音声を出力` の右）: `🎙 自分の声` / `🗣 翻訳の声`。ボタン 1 つで「仮想サウンドカードに何を流すか」を決められます ——
  押せば相手には自分の本当の声が届き、もう一度押せば翻訳音声が届きます。
- **ボタンが押せる条件**：プロキシがある **かつ** 翻訳が動作していること。翻訳音声モードへは「翻訳を開始」のあとでないと切り替えられません。
  **翻訳を停止すると自動で自分の声モードに戻ります**（最後の一文の翻訳音声が仮想マイクに残ることはありません）。仮想サウンドカードが未導入 / 開けないときはグレーアウトします。
- **翻訳を開始すると既定で翻訳音声モードになります**：「翻訳音声を出力」にチェックがあり、プロキシが使えるときは、
  「翻訳を開始」を押すと**自動で** `🗣 翻訳の声` に切り替わります（この切替ボタンを自分で押す必要はありません）。
  自分の声に戻したいときは 1 回押すだけです。「翻訳音声を出力」が未チェック / 方向に「自分」が含まれないときは
  **切り替えません** —— その場合の翻訳音声モードは無音になり、自分の声より悪くなるためです。
- **起動した時点でパススルー**：プログラムを起動した瞬間から、マイクはすでに仮想サウンドカードへ音を送っています（先に翻訳を開始する必要はありません）。VRChat 内でいつでも話せます。
- **「翻訳音声を出力」チェックボックスは、翻訳音声の経路の総スイッチのまま**です：チェックを外すと翻訳音声はマイクに入りません。この状態で「翻訳の声」を押すと「翻訳音声モードは無音になります」と案内が出ます。
- **実際に動き出した最初の一度だけ説明が出ます**：プロキシが実際に動いた最初の一度だけ、説明が表示されます ——
  仮想サウンドカードの**出力ストリームを常時占有**します。既定の再生デバイスが同じカードの場合、
  自分の声（エコー）が聞こえます。不要なら `設定 → マイクプロキシ` のチェックを外してください
  （カードはすぐに解放されます）。表示後は設定に記録され、以後は出ません。
- **「マイクプロキシ」をオフにする** = 旧来の動作に戻ります：仮想サウンドカードは翻訳の開始／停止に追従し、メイン画面のワンタッチ切替はなくなります。

設定項目は `⚙ 設定 → オーディオ → マイクプロキシ` にあり、変更は即時反映で、再起動は不要です：

| 項目 | 範囲 | 既定 | 説明 |
|---|---|---|---|
| 有効 | チェック | オン | オフにすると旧来の動作に戻ります |
| パススルーバッファ(ms) | 60–500 | 150 | 自分の声モードの遅延 / 途切れ耐性。⚠️ 60 未満にはしないでください —— マイクの 1 入力ブロックは約 100ms で、バッファの上限が 1 ブロックより小さいと各ブロックの大半が削られ、音がひどく途切れます |
| 翻訳音声バッファ(ms) | 50–2000 | 300 | 翻訳音声モードのジッタバッファ（`output.audio.buffer_ms` のことです） |

対応する `config.yaml`：

```yaml
output:
  audio:
    buffer_ms: 300               # 翻訳音声バッファ(ms)
    proxy:
      enabled: true              # マイクプロキシの総スイッチ
      passthrough_buffer_ms: 150 # パススルーバッファ(ms)、下限 60
      hint_shown: false          # 初回説明を表示済みか（アプリが自動管理。手で触る必要なし）
```

仮想サウンドカードを導入できない / 開けないときの挙動：ボタンは**グレーアウトして押せません**。ステータスバーとログにそれぞれ 1 行残ります
（ステータスバーの文言には `vlt/locales/ja.py` に対応する日本語版があり、ログの行はハードコードされた中国語なのでそのまま引用します）：
`マイクプロキシを使えません（仮想サウンドカードが開いていない？）。自分の声／翻訳音声の切替は無効です` / `[proxy] 代理不可用 → 回到旧行为：译音输出由引擎自建（随翻译启停），主界面「原声/译音」切换已禁用`；
chatbox / 手首オーバーレイ / デスクトップ字幕**はいつもどおり動作し**、影響はありません。

### 手首オーバーレイの微調整（「⚙ 設定 → 手首オーバーレイ」、14 個のスライダー、ドラッグで即反映）

| スライダー | 範囲 / 刻み | スライダー | 範囲 / 刻み |
|---|---|---|---|
| 位置 X / Y / Z | −0.30 ~ 0.30 m、0.005 | サイズ | 0.05 ~ 0.80 m、0.01 |
| ピッチ / ヨー / ロール | −180 ~ 180°、1 | カーブ | 0.0 ~ 0.50、0.01（1周に対する割合。0.5 = 半周 180°）|
| 不透明度 | 0.10 ~ 1.00、0.05 | 訳文の文字サイズ | 20 ~ 64、1 |
| 原文の文字サイズ | 14 ~ 48、1 | パネルの高さ | 240 ~ 560 px、10 |
| 背景の不透明度 | 0 ~ 255、5 | 原文の不透明度 | 0 ~ 255、5 |

ほかに **アンカー**のドロップダウン（右手 / 左手 / 外部トラッカー / HMD 前方固定）と **トラッカー番号**（0〜7）があります。
**位置・角度はアンカーごとに別々に保存**されます（`overlay.offsets.<アンカー>`）。ドロップダウンを切り替えると
そのアンカーの値が読み込まれるので、片方を調整しても他方を上書きしません（`overlay.offset` は
まだ個別保存していないアンカーの**フォールバック**）。左右の手のグリップ座標系は X 軸で鏡像なので、
左手は右手のコピーでは合いません（`rx` はそのまま、`ry`/`rz` を反転、位置の `x` も同様）。
変更は 200 ms のデバウンスでディスクに書き込まれ、**訳文の文字サイズ / 原文の文字サイズ / パネルの高さ /
背景の不透明度 / 原文の不透明度**はテクスチャを 1 フレーム再描画し、それ以外は変換行列の再適用のみです。
**背景の不透明度**は半透明の下地（小さくすると背景のシーンが透ける、255 で完全不透明）、
**原文の不透明度**は原文の行だけに効きます（「下地は半透明・文字は実体」にしたいなら 255 へ）。
いちばん上（外側）の**不透明度**は**レイヤー全体**の乗数で、底板も文字も一緒に薄くなります
（Windows 側の SteamVR `setOverlayAlpha` と同じ意味です）。

> 実測の目安：文字サイズ 42/30 + パネル 320 px で**会話 2 ラウンド**、36/24 + 420 px で**3 ラウンド・6 行**。

### デスクトップ字幕（VRChat のウィンドウに貼り付く字幕ウィンドウ・ヘッドセット不要）

**PC デスクトップモード向け**（issue #11）：「デスクトップ字幕」にチェックを入れると、**枠なし・
最前面・マウス透過**の字幕ウィンドウがすぐに表示され、チャット欄の直近数件を出します
（相手は左、自分は右）。

* **貼り付き**：既定では VRChat ウィンドウの**下端中央**に貼り付き、移動／解像度変更にも追従します。
  VRChat ウィンドウが見つからないときは固定座標に退避し、ログに 1 行残します。
* **位置**：**それ自身の**調整入口「設定 → デスクトップ字幕」→「ドラッグを解錠」→ 好きな位置へドラッグ →
  「位置を固定」（落点は「どのアンカー + どのオフセット」に換算して `config.yaml` に書き戻すので、
  VRChat ウィンドウが動いても同じ辺に貼り付いたままです）。
  マウス透過は既定でオン（VRChat のクリックを妨げません）。ドラッグには解錠が必要です。
* **不透明度**：同じ「設定 → デスクトップ字幕」のスライダー、0.20 ～ 1.00。ドラッグで即時反映、離すと書き込み。
* **設定**：`config.yaml` の `desktop_overlay:` セクション（`mode` を `latest` にすると
  「最新の一文だけ」の歌詞風になります）。⚠️ このセクションは**見た目用のキーを一式自分で持ち**
  （フォント / サイズ / 配色 / 行数 / 原文の有無 / パネル寸法）、手首オーバーレイの `overlay:`
  セクションとは**完全に独立していて互いに影響しません** —— デスクトップパネルは画面上の
  ピクセルパネル（px）、手首オーバーレイは VR 内のテクスチャ（メートル）で、そもそも別物です。
  `overlay:` を変えてもデスクトップ字幕は動かず、その逆も同じです。
* **Linux**：**Wayland セッション**（niri / sway / Hyprland / KDE など layer-shell 対応の合成器）
  では**ネイティブオーバーレイウィンドウ**：ピクセル単位の透明（本物の角丸・半透明の下地）、
  最前面・ゲームウィンドウへの追従・プロトコルレベルのマウス透過・ドラッグの保存まで Windows と同等。
  X11 セッション（XWayland を伴う GNOME/Weston を含む）は**ネイティブ ARGB オーバーレイウィンドウ**で
  動作します（ピクセル単位の alpha + X Shape によるマウス透過）。合成器（picom など）が必要で、
  無い場合は 1 ビットの形状マスクによる縮退動作（黒枠なし・角丸はギザギザ・下地は不透明）になり、
  ログに 1 行残ります。`desktop_overlay.backend` で経路を強制できます
  （描画トラブルの切り分けに便利）——境界は [GUIDE.linux.md](GUIDE.linux.md) の「デスクトップ字幕」を参照。

> ⚠️ VRChat は**ウィンドウモード / ボーダーレス**である必要があります（Unity の
> `Fullscreen mode = 3`、VRChat の既定値）。排他フルスクリーンではサードパーティの最前面
> ウィンドウは必ず隠れます——これは本プログラムのバグではありません。
> レンダリングをオフラインで確認：`python -m vlt.output.desktop_overlay --demo --out out/desktop_frames`。

### 複数人ルーム（何人かでお互いの字幕を見る）

**「大勢で一緒に遊びたいけれど、ボイスチャンネルがローカルプレイヤーの言語で埋まってしまう」場面向け**：
それぞれが**自分用に**本プログラムを 1 つずつ起動し、**同じルームコード**を入力して同じルームに接続すると、
各自の手首オーバーレイ / デスクトップ字幕に**お互いの話した内容**が表示されます。

* **始め方**：`⚙ 設定 → ルーム` → **ルームコード**（8 文字、両端で必ず同じもの。思いつかなければ
  「ランダム生成」を押して、できたコードを相手に読み上げてください）と**ニックネーム**（空欄なら
  システムのユーザー名）を入力 → 設定を閉じる → メイン画面の 3 行目で **「ルームに接続」**を押します。
  接続できるとボタンが**赤茶色の「切断」**に変わり、右側に `状態：接続済み · N 人` と表示されます。
* **話すには先に「翻訳を開始」**：ルームに流れるのは**自分の発話の認識原文**（翻訳はしません）で、
  その原文はマイク側から来ます —— 翻訳していなければ他人の発話を受け取るだけで、自分からは送れません。
  方向に「自分」を含めてください。
* **ルームコード**：8 文字の Crockford Base32 で、文字集合から**読み間違えやすい `I / L / O / U` を
  除いてあります**。手入力はかなり寛容です：`I`、`L` は `1` として、`O` は `0` として扱われ、
  ハイフンと空白は無視されます。同じルームに入るには、相手に**同じコード**を渡す必要があります。
* **ブロードキャストされるのは自分の発話だけ**：ゲーム音声を取り込む側（loopback）は明示的に
  除外されています —— 他人の発話が自分を経由して再配信されることはなく、ループも生まれません。
* **手首オーバーレイは人ごとに色分け + ニックネーム表示**：ルームで複数人が同時に話しても誰が
  話しているか分かります。チャット欄とデスクトップ字幕でも同じように表示されます。
* **変更は即時反映**：ルームコード / ニックネームは変更するとすぐ `config.yaml` に書き込まれ、
  すでに接続している場合は新しい設定で**再接続**します。
* **設定**：`config.yaml` の `room:` セクション（画面から設定できるのはルームコードとニックネーム
  だけで、残りは直接編集してください）

  ```yaml
  room:
    enabled: true                      # 「ルームに接続」を押すと true になり、次回起動時も記憶されます
    server_url: "wss://vlt-room.kcm-nixi.cn/ws"
    room_code: "TESTTEST"              # 8 文字、両端で必ず同じもの
    nickname: ""                       # 空 = システムのユーザー名を使用
    broadcast_source: true             # 「自分」の発話をルームへ送る
    show_remote: true                  # 他人の発話を手首オーバーレイ / チャット欄に表示する
  ```
* **サーバー**：`server/` にある Cloudflare Worker（ルームごとに Durable Object が 1 つ）で、
  **文字を運ぶだけ**です：翻訳もせず、保存もせず、ルームが空になれば自動で回収されます。
  自分で立てる場合は [server/README.md](../server/README.md) に従ってデプロイし、`server_url` を
  自分のアドレスに向けてください。
* **本バージョンは文字を運ぶだけで、音は出しません**：TTS を回し込むための口は用意してありますが、
  本バージョンでは開放していません。

> ⚠️ 既知の制限：ルーム内の各人の**メンバー番号は、接続のたびにサーバー側でランダムに生成されます**。
> そのため「同じ人が再接続しても色が変わらない」は**成り立ちません** —— 誰かが切断してつなぎ直すと、
> あなたの画面では別の色になります。実際には**ニックネーム**で人を見分けてください
> （ニックネームは変わりません）。

## 7. トラブルシューティング

| 症状 | 原因 / 対処 |
|---|---|
| 吹き出しに何も出ない | VRChat が起動していない／OSC がオフ／吹き出しの表示が Off。`--dry-run` で送信ログが出るならプログラム側は正常です |
| `[loopback] ❌ no loopback device found` | VRChat が音を再生していない、または**リモートデスクトップ経由で操作している**（WASAPI のエンドポイントはセッションごとに分離されるため、物理マシンの現在のセッションで動かす必要があります） |
| マイクが何も拾わない | 上と同じ。まず「⚙ 設定」のドロップダウンで選ばれているデバイスを確認してください（リモートセッションでは列挙が空になるのが正常である旨、ステータスバーに表示されます）。ログで `[mic]` を検索：「已回落到同名设备」はこのサウンドカードの WASAPI 端点が開けず、プログラムが同じ名前の別インターフェースへ自動で切り替えた正常動作です。「所有候选设备都打不开」なら本当の故障です |
| `Voice 'Chelsie' is not supported` | `session.voice` が未設定です。`Tina` のままにしてください |
| `Invalid translation parameter` | `session.update` に `translation` フィールドがありません（コード側では保証済み。改変するときは注意） |
| `1007 Requests rate limit exceeded` | RPM 10 に到達しました。1 分待ってください。頻繁な再起動は避けてください（**WS 接続 1 回ごとにリクエスト 1 回**と数えます） |
| 翻訳が文の途中で止まる | 無音フォールバックのしきい値が下がっています。`session.final_silence_s` は 2.3 s より大きく（既定 3.0） |
| 話し終えてから最終版まで ~3s かかる | 早めの確定が無効（`session.fast_final_silence_s: null`）か効いていない。判定は**レベル**：騒がしい環境では上の 3.0s に退化する（保守的で、途中で確定しない） |
| `[overlay] ⚠️ SteamVR not running or unavailable` | 正常な縮退動作です。手首オーバーレイが出ないだけで、chatbox には影響しません |
| 手首オーバーレイが見えない | まず SteamVR が起動しているか確認し、「設定 → 手首オーバーレイ」で位置／サイズを調整してください。`--overlay-dry-run` で PNG が出るなら描画自体は正常です |
| しばらくすると手首オーバーレイが消える | 2 段階の自己修復が入っています（3 回連続失敗 → オーバーレイを再構築 → さらに 3 回 → openvr 接続をハード再起動 → 以降は 50 回に 1 回だけ再試行）。ログには 30 秒ごとに `[overlay][diag] heartbeat: …` が出て、「最後の成功からの経過時間／再構築回数」を確認できます |
| 翻訳音声が出ない | ① 2 つのスイッチが両方オンか（出力チェックと方向ごとの設定）② 「自分」方向でのみ動作します ③ 仮想サウンドカードは入っていますか。理由はステータスバー／ログに明示されます ④ **それ以外の機能には影響しません** |
| GUI で「翻訳を開始」を押しても何も起きない | まずターミナルの出力を確認してください。asyncio コールバック内の例外は 1 行のトレースバックがコンソールに出るだけで、ステータスバーには出ません（exe の場合は `logs/` の最新 `.log`） |
| 意味の分からないエラー | **「⚙ 設定 → ログを ZIP でエクスポート」** — 自動で秘匿処理されます。ZIP をメンテナーに送ってください |

## 9. 開発

### テストの実行

**pytest は使いません**（依存に入っていません）。各テストファイルは独立した実行可能スクリプトで、CI が動かすものと同一です：

```bat
:: 全部（ファイル単位、CI と同一。cmd に直接貼り付け — .bat ファイル内では %t を %%t に）
for %t in (tests\test_*.py) do @.venv\Scripts\python.exe %t

:: 単体
.venv\Scripts\python.exe tests\test_virtualmic.py
```

テストは**すべてオフラインで動作します**（マイク / VRChat / SteamVR / ネットワーク不要）。デバイスの解決、パスの決定、
再接続、ログのローテーションと秘匿処理、サポートポップアップ、手首オーバーレイの自己修復、
翻訳音声バッファの不変条件、コメントを保つ設定の書き戻しなどをカバーしています。

唯一の例外は `tests/test_engine.py` で、実際のセッションを 1 つ開くため**そのマシンに設定済みの API key が必要**です。
CI では明示的にスキップされます（ワークフローが理由を `::notice::` で出力します — 黙ってスキップはしません）。

1 コマンドでまとめて実行したい（ついでにカバレッジも出したい）ときは、リポジトリ同梱のランナーも使えます：

```bat
.venv\Scripts\python.exe scripts\run_tests.py             :: ファイル単位で実行、test_engine.py は自動でスキップ
.venv\Scripts\python.exe scripts\run_tests.py --coverage  :: カバレッジの要約も出力（しきい値は設けない）
.venv\Scripts\python.exe scripts\run_tests.py --only i18n  :: 名前に i18n を含むテストだけ実行
```

コードを変更したら、ついでに静的チェックも 1 回実行してください（CI では**ブロッキング**のゲートです）：

```bat
.venv\Scripts\python.exe -m ruff check --select F,E9 .
```

### パッケージング

```bat
build_exe.bat                                              :: ビルド + その後の自己チェック
.venv\Scripts\python.exe scripts\build_exe.py --no-verify  :: ビルドのみ
```

出力は `dist\VRChatLiveTranslate.exe`：PyInstaller の**単一ファイル・コンソールウィンドウなし**で、
`config.example.yaml` / `testdata` / `assets` を同梱し、約 37 MB です。
既定ではビルド後に `exe --self-test` を実際に 1 回実行し、ログに `GUI_SELFTEST_OK` が出たときだけ合格とみなします。

### CI / リリース

- **CI**（`.github/workflows/ci.yml`、main への push / PR / 手動）：
  構文チェック → **静的チェック（ruff の `F,E9`、ブロッキング）** → 認証情報スキャン → オフラインテストをファイル単位で全実行（ついでにカバレッジを累積し、末尾に要約を出力。**しきい値なし・非ブロッキング**）→ さらに別途**パッケージング工程**の確認（成果物が存在し 20 MB 以上）
- **リリース**（`.github/workflows/release.yml`、`v*` タグの push で起動）：
  まずタグと `vlt/__init__.py` の `__version__` を突き合わせ（不一致なら即失敗）→ **exe と Linux の AppImage** をパッケージ →
  **exe**、**`VRChatLiveTranslate-x86_64.AppImage`**、`SHA256SUMS.txt` を添付した Release を作成（チェックサムは GitHub が添付の横に `sha256:…` として表示します。このファイルは v0.2.0 以前のクライアント向けの移行措置です）
- **ダウンロードしたものを自分で検証したい場合**：`scripts/verify_release.py` が Release の成果物を取得して突き合わせます
  （SHA256、`--self-test` の実実行、バージョン行、新機能の文字列をバイトコードから検索、アイコンのピクセル比較）：

  ```bat
  .venv\Scripts\python.exe scripts\verify_release.py v0.10.0 "MicProxy,toggle_voice_mode,chatbox_text,passthrough_buffer_ms,意大利语"
  ```

## 10. 既知の制限

- 手首オーバーレイには **SteamVR がアクティブなコンポジタであること**が必要です。ベンダー純正の OpenXR ランタイムでは、サードパーティ製の PC 側オーバーレイは表示されません
- 入力側は**ゲームのミックス音声の 1 ステレオチャンネルしか取得できません**：話者ごとのチャンネルは存在しないため、複数人が同時に話すと話者の特定は原理的に不正確です
- WebSocket 経路には**エコーキャンセルもノイズ抑制もありません** → **ヘッドホンの着用が必須**です（スピーカーだと相手の声も拾ってしまい、同じ文が二重に認識されます）
- 両方向を同時に翻訳する = WebSocket セッション 2 本で、予算も両方に計上されます
- **タイピング + 読み上げは「翻訳 + TTS」の 2 リクエスト**です。テキストはほぼ即座に出ますが、音声は TTS の合成待ちになります（実測でエンドツーエンド約 2.6 秒）。
  そのため吹き出しで見えてから 1〜2 秒遅れて相手に届きます。声は TTS の音色（既定 `Cherry`）で、音声経路のリアルタイムモデルの声とは**同じではありません**。
  条件は 3 つ目の系統と同じで、「翻訳音声を出力」がオンかつ仮想サウンドカードがある場合のみ。それ以外は自動でスキップされ、テキストだけになります
- **タイピングはマイクの代替**です：そのため方向に「自分」が含まれるときだけ使え、かつ「翻訳を開始」を押した後でのみ有効です
- **ルームに流れるのは「自分の発話の認識原文」で、訳文ではありません**。しかも送信するには**先に「翻訳を開始」を押す**必要があります。
  ルーム内の人が見るのはあなたの原文です（各人の表示言語が違っても自動翻訳はされません）
- **ルームメンバーの色は再接続で変わります**：メンバー番号は接続のたびにサーバー側でランダムに生成されるため、
  「再接続しても同じ色のまま」は成り立ちません —— ニックネームで人を見分けてください
- **chatbox に載るのは「自分が話した内容」の訳文だけ**です：相手の発話の訳文は chatbox の吹き出しには入りません。手首オーバーレイか GUI のチャット欄を見てください
