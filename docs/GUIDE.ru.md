## 0. Самый быстрый старт: скачать готовый exe

Возьмите **`VRChatLiveTranslate.exe`** из
**[Releases](https://github.com/nixi-agent/vrchat-livetranslate/releases/latest)**
(**один файл, установка не нужна, окна консоли нет**) и запустите двойным щелчком.

- **API-ключ Qwen Cloud** нужен свой: вставьте и сохраните его в «⚙ Настройки»
- Конфигурация и журналы лежат в `%APPDATA%\vrchat-livetranslate` (работает, даже если exe лежит в папке только для чтения)
- Нужна портативная сборка (конфиг рядом с exe) → положите рядом с exe **пустой файл `portable.txt`**
- Если старая версия оставила `config.yaml` / `logs/` рядом с exe, при первом запуске они **автоматически переносятся** в новое место; исходные файлы не удаляются

### Обновляется ли он сам?

**Проверяет автоматически, но никогда не устанавливает сам** — обновляться и когда, решаете только вы:

- При каждом запуске он один раз тихо проверяет обновления в фоне. Если проверка не удалась (например, нет сети), он не мешает, а просто пишет в журнал
- Когда найдена новая версия, появляется окно с тремя вариантами:
  - **Обновить сейчас** → скачивание автоматически (примерно минута-другая); по завершении нажмите «Перезапустить и обновить», чтобы переключиться сразу,
    либо «Обновить позже» — замена произойдёт при закрытии программы, и следующий запуск будет уже новой версией
  - **Позже** → в этом запуске больше не показывает, проверит снова при следующем запуске
  - **Пропустить эту версию** → игнорирует только эту версию; про следующую сообщит снова
- Скачивание не удалось → можно повторить либо нажать «Открыть страницу загрузки» в окне и скачать из Releases самостоятельно
- Хочется проверить, когда окна нет → «⚙ Настройки → Обновление программы → Проверить обновления»
- Обновление **не трогает вашу конфигурацию и API-ключ**; после успешного обновления следующий запуск вам об этом сообщит

**Если вы запускаете из исходников**: всё вышесказанное не применяется — просто выполните `git pull` в репозитории
(при нажатии «Обновить сейчас» в исходном запуске программа скажет то же самое).

Хотите почитать исходники / собрать самому / дописать что-то → начните с раздела «1».

## 1. Что нужно заранее

1. **Windows 10 / 11** (используются WASAPI и SteamVR)
2. **Python 3.11** (3.12 не проверялся; при установке обязательно отметьте *Add python.exe to PATH*) — *не нужно, если пользуетесь только exe*
   <https://www.python.org/downloads/release/python-3119/>
3. **VRChat**: включите OSC в настройках (`OSC enabled: True`) и выставьте видимость чат-пузырей в **Everyone**
4. **SteamVR** — нужен только для функции «собеседник говорит → экран на запястье»
5. **API-ключ Qwen Cloud** (достаточно личной верификации по паспорту)

## 2. Установка (из исходников)

Запустите двойным щелчком **`setup.bat`** (создаст `.venv` и поставит зависимости, 1–2 минуты).

Вручную то же самое:

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements-windows.txt
```

## 3. Настройка API-ключа

> 🔑 Ещё нет аккаунта Qwen Cloud? → **[Регистрация в Qwen Cloud ▸](https://www.qianwenai.com/)**

Источники перебираются в порядке ниже — **побеждает первый найденный**:

| Приоритет | Источник | Как задать |
|---|---|---|
| 1 | Ключ, сохранённый в интерфейсе | Вставьте и сохраните в «⚙ Настройки → API key» (хранится в `%USERPROFILE%\.vrchat-livetranslate\api_key.txt`) |
| 2 | Переменная окружения | `setx DASHSCOPE_API_KEY "sk-your-key"` (**действует только в новом открытом терминале**) |
| 3 | Конфигурация Bailian CLI | `bl auth login --api-key "sk-your-key"` (нужен `npm install -g bailian-cli`), читается из `%USERPROFILE%\.bailian\config.json` |

**Ключ читается только из этих трёх мест и никогда не записывается в файлы проекта или `config.yaml`.**

> 🔒 **Безопасность коммитов**: в репозитории есть сканер учётных данных. Один раз выполните `install_secret_guard.bat`,
> чтобы поставить pre-commit-хук, и любой коммит с `sk-...` / `gho_...` / `AKIA...` / `Bearer ...`
> или иным зашитым секретом будет отклонён на месте (скрипт: `scripts/check_no_secrets.py`).
> Полная проверка вручную: `python scripts/check_no_secrets.py --once`
> Причина: как только ключ попал в историю git, удаление файла его не убирает — пришлось бы переписывать историю.
> Лучше остановить это до коммита.

### Пользователям за пределами материкового Китая: Qwen Cloud (зарубежная версия)

**Зачем две линии**: линия по умолчанию («Qwen Cloud», `qianwen`) обслуживает только материковый
Китай — из-за рубежа даже не зарегистрироваться, а прямое подключение нестабильно. За пределами
Китая используйте **Qwen Cloud (зарубежная версия)**, <https://www.qwencloud.com/>: те же модели,
тот же realtime API (синхронный перевод, перевод набранного текста и озвучка — всё на месте),
отличаются только адрес входа и система аккаунтов. Две линии **взаимоисключающие**: работает ровно
одна — та, что выбрана в приложении.

**Три шага для регистрации** (всё на <https://www.qwencloud.com/>):

1. Регистрация через **Google / GitHub / код на e-mail** — **ни телефона, ни банковской карты**
2. Создайте API-ключ в консоли (начинается с `sk-ws-`)
3. У новых аккаунтов есть бесплатная квота (считается по каждой модели); пополнять нужно только
   после её исчерпания

**Три шага в приложении**:

1. `⚙ Настройки → Общие → Сервисная линия` → выберите «Qwen Cloud (зарубежная версия)»
2. Нажмите «Сохранить настройки линии» (это перепишет `base_url` на
   `wss://maas.qwencloudapi.com/api-ws/v1/realtime`)
3. Вставьте ключ в поле «API key» выше и сохраните, затем **запустите перевод заново**

> 🔑 **Ключи двух линий не взаимозаменяемы**: у зарубежной и материковой линий свой файл ключа
> (`api_key.txt` / `api_key_qwencloud.txt`), поэтому при переключении **не нужно** вводить ключ
> заново. Строка состояния «Текущая линия: источник sk-****6789» следует за активной линией.
> Один и тот же аккаунт **не может** использовать один ключ на обеих линиях — получите отдельный
> ключ. Чтобы смена линии вступила в силу, **запустите перевод заново** (если он уже идёт,
> приложение предложит сначала остановить его).

> ⚠️ **Старые конфигурации мигрируют автоматически**: если вы раньше выбирали «Alibaba Cloud Model
> Studio (международная версия)» (нужны были ID рабочего пространства и регион, а при регистрации
> из-за рубежа могли запросить выписку по карте), то с этой версии при запуске произойдёт
> автоматический переход на Qwen Cloud (зарубежная версия), о чём будет сказано в логе — не забудьте
> ещё раз ввести ключ этой линии.

**Два ключа `config.yaml`** (записываются на месте при нажатии «Сохранить настройки линии» — руками
править не нужно):

```yaml
session:
  provider: qianwen          # id линии: qianwen (материковый Китай) / qwencloud (зарубежная)
  base_url: wss://maas.qianwenaiapi.com/api-ws/v1/realtime
```

После переключения на зарубежную линию `base_url` становится таким:

```yaml
  base_url: wss://maas.qwencloudapi.com/api-ws/v1/realtime
```

**Именно `base_url` определяет, куда реально идут запросы**; `provider` задаёт только значение по
умолчанию в интерфейсе и то, какой файл ключа используется. У обеих линий одинаковые три пути
(`/api-ws/v1/realtime`, `/compatible-mode/v1/chat/completions`,
`/api/v1/services/aigc/multimodal-generation/generation`), поэтому смена линии меняет только
`base_url`.

> 🔍 **Диагностика**: строка `[net] 线路=… host=…` в логе — это адрес, по которому идёт трафик, а
> `[gui] 服务线路已保存：…` — то, что интерфейс записал на диск. Если они расходятся, значит линия
> изменена, но перевод не перезапущен.

## 4. Самопроверка

**Если пользуетесь exe**: запустите и убедитесь в трёх вещах —

1. В «⚙ Настройки» ни один из трёх списков устройств не пуст (`Микрофон` / `Звук VRChat` / `Вывод озвучки`)
2. Статус API-ключа — **настроен** (иначе щелчок откроет страницу регистрации)
3. Отметьте `chatbox`, нажмите «Начать перевод», скажите одну фразу в микрофон → в пузыре появится перевод

**Если из исходников**: запустите двойным щелчком **`run_selfcheck.bat`**. Он делает четыре вещи по порядку, первые три не требуют ни микрофона, ни VRChat:

1. Проверка импорта модулей (engine / session / overlay / chatbox / merger)
2. Читает API-ключ один раз и печатает его замаскированным (подтверждает порядок приоритета)
3. Отрисовывает один кадр экрана на запястье офлайн (не занимает SteamVR)
4. Прогоняет встроенный тестовый звук через весь конвейер (китайский → английский, в chatbox)

Если VRChat запущен, в пузыре должно появиться:

```
Hello, I'm Nixi. Today, we're going to test out the real-time simultaneous interpretation feature in VRChat.
```

**Перед сообщением об ошибке обязательно выполните эту самопроверку.**

## 5. Использование

### Графический интерфейс (рекомендуется)

**Запустите exe двойным щелчком**, а при установке из исходников — **`run_gui.bat`**: окно одинаковое
(Tkinter, только стандартная библиотека, никаких лишних зависимостей, открывается мгновенно).

| Область | Содержимое |
|---|---|
| Первая строка | `Начать перевод` ⇄ `Остановить перевод` (**одна и та же кнопка**: пока перевода нет — синяя «Начать перевод», во время перевода — красная «Остановить перевод», нажатие переключает), переключатель направления (`Я` / `Собеседник` / `В обе стороны`), список языковой пары (исходный → целевой), справа `☕ Поддержать` и `⚙ Настройки` |
| Вторая строка | `Вывод:` с флажками `chatbox` / `Экран на запястье` / `Субтитры на рабочем столе` / `Вывод озвучки`; кнопка справа от `chatbox` переключает, **что показывать в пузыре — оригинал или перевод**; при отмеченном `Вывод озвучки` справа появляется ещё кнопка `🎙 Оригинал` / `🗣 Перевод` (решает, что услышит собеседник, см. раздел «Микрофонный прокси»; неактивна, если виртуальная звуковая карта не установлена); справа статус API-ключа (при наличии — `API-ключ настроен`, **иначе кликабельная надпись «⚠ API-ключ не настроен ・ Подключить Qwen Cloud ▸»**). **Тонкая настройка экрана на запястье / субтитров на рабочем столе — в «⚙ Настройки»** (`Настройки → Экран на запястье` / `Настройки → Субтитры на рабочем столе`) |
| Область чата | Синие пузыри справа — что сказали вы, серые слева — что сказал собеседник; в пузыре две строки — **сверху оригинал мелким шрифтом, снизу перевод крупным**; история прокручивается (до 500 записей) |
| Строка состояния | Слева: цветная точка и последнее сообщение; справа: статистика (`Работает` / `Переведено: {n}` / `Первая порция {ms} мс`); они никогда не перекрываются |
| Нижняя строка | **Ввод текста**: поле `Ввод:` и кнопка `Отправить`, **Enter — отправить** (`Esc` — очистить). Доступно, только когда направление включает «Я», иначе поле неактивно |
| Окно `☕ Поддержать` | Кнопка-ссылка Ko-fi и QR-коды WeChat / Alipay (пропорционально уменьшены до 240 px, сканируются сразу) |

- **Потоковый вывод**: нефинальные порции **перерисовывают тот же пузырь на месте**, а не добавляют новый на каждую порцию
- **В обе стороны**: два направления перевода в одном окне (микрофон → правая сторона, звук игры → левая); второе **стартует со сдвигом 300 мс**, чтобы не драться за аудиоустройство; если одна сторона падает, вторая продолжает работать
- **Зеркалирование языков**: одна пара покрывает оба направления — выберите «китайский → английский», и направление собеседника автоматически станет «английский → китайский».
  Исходный язык выбирается из `Автоопределение` / китайский / английский / японский / корейский / французский / немецкий / испанский / русский / тайский / итальянский (в целевом списке то же самое, но без «Автоопределения»).
  Если в качестве исходного выбран `Автоопределение`, целевой язык обратного направления откатывается к китайскому, и строка состояния об этом сообщает. Изменения **вступают в силу сразу**, пишутся в конфигурацию и сохраняются между запусками
- **Окно настроек** (`⚙ Настройки`, вкладки): `Общие` (ввод / очистка API-ключа, язык интерфейса, OSC-порт VRChat), `Звук` (три списка аудиоустройств + `Обновить`, порог, голос), `Экран на запястье` (ползунки тонкой настройки), `Субтитры на рабочем столе` (размер / шрифт / прозрачность окна субтитров), `Словарь`, `Комната`, `О программе` (версия и раздел журналов `Экспорт журналов…`)
- **Настройки → Экран на запястье**: у **экрана на запястье** (той самой текстуры в шлеме) привязка + 14 ползунков, **тяните — применяется на лету, перезапуск не нужен**. Он и «Настройки → Субтитры на рабочем столе» **не влияют друг на друга** (две полностью независимые конфигурации: одна — метрическая текстура в VR, другая — пиксельная панель на экране)
- **Настройки → Субтитры на рабочем столе**: у приклеенного к окну VRChat окна субтитров свои «Размер перевода» / «Размер оригинала» / «Ширина панели» / «Высота панели» / «Прозрачность» / «Разрешить перетаскивание»
  (у обеих — параметры, которые **настраивают один раз и больше не трогают**, поэтому они и не занимают место в главном окне; изменения применяются сразу)
- **Ввод текста**: когда не хочется говорить, используйте клавиатуру — наберите в нижней строке и **нажмите Enter**. Перевод идёт по **точно такому же** пути, что и речь (пузыри чата / экран на запястье / chatbox); при включённом «Выводе озвучки» он **ещё и произносится**: перевод синтезируется через TTS и записывается в виртуальную звуковую карту, так что собеседник его слышит (см. `text_input.tts` в «6. Конфигурация»). Это **замена микрофона**, поэтому доступно только когда направление включает «Я» (иначе поле неактивно)
- **Переключатель `chatbox` действует сразу**: во время перевода отметьте / снимите `chatbox` во второй строке — **без остановки и перезапуска**: после включения со следующей порции перевод идёт в пузырь, после выключения перестаёт (уже показанная строка остаётся и гаснет сама), сессия не пересоздаётся. Пузырь шлёт только перевод **вашей** речи; если направление не включает «Я», в статусной строке появится подсказка

#### Автоматическая приёмка (без окна, headless)

```bat
:: установка из исходников
.venv\Scripts\python.exe -m vlt.gui --self-test
.venv\Scripts\python.exe -m vlt.gui --self-test-dual

:: exe (окна консоли нет; результаты идут в журнал — именно так самопроверяется сборка)
VRChatLiveTranslate.exe --self-test
```

При успехе печатает `GUI_SELFTEST_OK` / `GUI_SELFTEST_DUAL_OK mine=N theirs=N`, при ошибке — `..._FAIL: ...` в stderr и ненулевой код возврата. Требуется настоящий API-ключ.

> 🪵 **Журналы сбоев**: при каждом запуске интерфейс пишет `gui_<отметка времени>.log` в `logs/`,
> где есть **сведения о версии** (git HEAD), окружение Python и весь stdout/stderr (**каждая строка с отметкой `HH:MM:SS.mmm`**).
> Подключены четыре вида перехвата: нативные сбои (`faulthandler`), исключения главного потока, исключения дочерних потоков и исключения обратных вызовов Tk.
> При сбое **достаточно отправить этот файл разработчику, чтобы найти причину** — без него после закрытия окна не остаётся ничего.
> Один файл ротируется на 2 МБ; когда суммарный объём журналов превышает 5 МБ, самые старые удаляются. В «Настройках» всё можно выгрузить одним **обезличенным** архивом.

### Командная строка (только для установки из исходников)

exe — это однфайловый графический интерфейс без окна консоли; кроме `--self-test` выше у него нет командной строки. CLI имеет смысл только при установке из исходников.

```bat
:: Я говорю → chatbox (реально отправляется в VRChat)
.venv\Scripts\python.exe -m vlt.app --direction mine --mic --sink chatbox

:: Собеседник говорит → экран на запястье (нужен запущенный SteamVR)
.venv\Scripts\python.exe -m vlt.app --direction theirs --loopback --sink overlay

:: Проверить конвейер без VRChat: прогнать встроенный тестовый звук
.venv\Scripts\python.exe -m vlt.app --direction mine --pcm testdata\zh_test_16k.pcm --dry-run
```

Чтобы переводить оба направления одновременно → **откройте два окна командной строки** (либо используйте «В обе стороны» в интерфейсе — там два сеанса в одном окне).
У каждого направления своя сессия WebSocket, они не мешают друг другу (лимит RPM 10, с запасом).

Если команды кажутся длинными, есть готовые bat-файлы: **`run_chatbox.bat`** (я говорю → пузырь; сначала показывает устройства, потом запускается)
и **`run_overlay.bat`** (собеседник говорит → экран на запястье).

#### Все параметры

| Параметр | Действие |
|---|---|
| `--direction mine/theirs` | Какое направление из `config.yaml` использовать |
| `--mic` / `--loopback` / `--pcm <file>` | Источник звука: микрофон / вывод воспроизведения VRChat / офлайн-PCM (что-то одно; приоритет `--pcm` > `--mic` > `--loopback`) |
| `--sink chatbox/overlay/both` | Куда выводить (по умолчанию `chatbox`) |
| `--list-devices` | Показать аудиоустройства ввода/вывода и выйти |
| `--dry-run` | Не отправлять OSC по-настоящему; только печатать и сбрасывать пакеты |
| `--overlay-dry-run` | Overlay не занимает SteamVR; каждый кадр сохраняется в PNG в `out/overlay_frames/` |
| `--audio-out` | Включить вывод озвучки (переопределяет `output.audio.enabled` в `config.yaml`) |
| `--audio-device <name...>` | Цепочка имён виртуальной звуковой карты (переопределяет значение по умолчанию в `config.yaml`) |
| `--no-realtime` | Подавать PCM как можно быстрее (без ограничения реального времени; имеет смысл только с `--pcm`) |
| `--settle-s <seconds>` | Сколько секунд ждать ответы после конца звука (по умолчанию 8) |
| `--config <path>` | Использовать другой файл конфигурации |

> Захват микрофона работает **непрерывно**: до `Ctrl+C` (параметра длительности нет).
>
> 📌 **Флаг для выбора аудиоустройств не нужен**: выберите в «⚙ Настройки» (первый пункт списка «Автоопределение» перебирает цепочку резервных вариантов)
> либо отредактируйте `capture.mic_device` / `capture.loopback_device` в `config.yaml`.
> Сохраняется **строка с именем устройства**, а не индекс — индексы целиком сдвигаются при подключении устройств и смене сеанса.
>
> ⚠️ **В списке только включённые устройства, и каждая звуковая карта — один раз**: приложение
> перечисляет только эндпоинты **WASAPI** — то есть те, что **включены** в «Звук» Windows
> (выключенные не показываются; чтобы ими пользоваться, включите их в «Звук → Дополнительные
> параметры звука»). Поэтому «один и тот же микрофон двумя-тремя строками с разной частотой»
> больше не встречается, а частота в скобках — **та, что реально используется** (обычно 48000).
> Имена из старых конфигов по-прежнему разрешаются — они попадают на одноимённый эндпоинт WASAPI.

## 6. Конфигурация (`config.yaml`)

> 📄 **При первом запуске `config.yaml` создаётся автоматически из `config.example.yaml`.**
> `config.yaml` — это **ваша собственная конфигурация** (выбор устройств, языковые предпочтения и т. п.);
> она в .gitignore и **никогда не попадает в систему контроля версий**, потому что имена устройств у всех разные
> и только мешали бы друг другу. Чтобы вернуть значения по умолчанию — удалите файл и запустите снова.
>
> Где он лежит:
> - **exe**: `%APPDATA%\vrchat-livetranslate\config.yaml` (в портативной сборке с `portable.txt` — рядом с exe)
> - **Из исходников**: `config.yaml` в корне репозитория
>
> 🛟 **Сломанная конфигурация не мешает запуску**: если разбор YAML не удался, файл автоматически сохраняется как
> `config.yaml.broken`, из шаблона создаётся новый с понятным пояснением, и запуск продолжается.

Всё, что вы меняете в интерфейсе (направление, флажки вывода, языки, устройства, настройка экрана на запястье), **записывается обратно на место** в этот файл —
меняется только эта строка; **комментарии, пустые строки и порядок ключей полностью сохраняются** (сгенерированный YAML проверяется перед записью; некорректный вывод отклоняется).

### Основные ключи

```yaml
session:
  model: qwen3.8-livetranslate-flash-realtime   # можно и qwen3.5-*（имена событий разводятся по поколению автоматически）
  base_url: wss://dashscope.aliyuncs.com/api-ws/v1/realtime
  voice: Tina                 # ⚠️ указывать обязательно, иначе Voice 'Chelsie' is not supported
  turn_detection: null        # пусто = значение сервера по умолчанию
  final_silence_s: 3.0        # ⚠️ должно быть больше серверного интервала порций (на практике до 2.3 с), иначе финальная версия выскочит посреди фразы
  fast_final_silence_s: 1.1   # Быстрое завершение: если и источник молчит (никто не говорит) — финализировать после такой паузы текста (экономия ~1.8s); null = выключить
  fast_final_user_quiet_s: 0.5  # «Никто не говорит» определяется по **уровню**; в шумной обстановке быстрый путь деградирует до 3.0s выше
  max_new_sessions_per_minute: 4   # бюджет RPM 10: каждое подключение WS считается одним запросом
  reconnect_backoff: [2, 5, 10, 30]

capture:                      # пустая строка = автоопределение
  mic_device: ""
  loopback_device: ""

directions:
  mine:   { source_lang: zh,   target_lang: en, output_audio: false }   # я → пузырь
  theirs: { source_lang: null, target_lang: zh, output_audio: false }   # собеседник → экран на запястье (null = автоопределение)

chatbox:
  interval_s: 2.0             # частота обновления порций (дырявое ведро 5 записей/5 секунд → одна в 2 секунды с запасом)
  max_chars: 144              # официальный предел (символы, не байты)

text_input:                   # ввод текста (поле внизу, Enter — отправить)
  enabled: true               # false = строка ввода не отображается
  model: qwen-mt-flash        # для набора текста используется **текстовая** модель перевода; можно qwen-mt-plus
                              # ⚠️ не ставьте qwen3-livetranslate-flash: на практике его текстовый интерфейс возвращает вход как есть
  timeout_s: 20               # таймаут одного перевода (секунды)
  tts:                        # озвучивать и набранный текст (перевод синтезируется через TTS → виртуальная звуковая карта → собеседник слышит)
    enabled: true             # нужны включённый «Вывод озвучки» и направление с «Я»; иначе шаг пропускается и остаётся только текст
    model: qwen3-tts-flash    # можно qwen3-tts-instruct-flash
    voice: Cherry             # многоязычный голос (китайский/английский/японский проверены)
    timeout_s: 30

merger:
  interval_s: 2.0             # первая порция сразу, затем снимок каждые 2 секунды, в конце фразы обязательно финал
  carry_over: false           # true = сохранять предыдущий финальный перевод как префикс (ощущение непрерывных субтитров)

overlay:
  interval_s: 0               # 0 = показывать сразу при обновлении (локальный вывод не ограничен лимитом chatbox)
  anchor: right_hand          # left_hand | right_hand | tracker | hmd
  size_px: [1024, 320]
  font_size: 42               # размер перевода
  source_font_size: 30        # размер оригинала
  show_source: true           # две строки (3.8 и так возвращает распознанный оригинал, доплаты нет)

output:
  audio:
    enabled: false            # общий выключатель озвучки: логическое «И» с directions.<X>.output_audio
    device_name: ""           # вручную заданное имя виртуальной звуковой карты (если непустое, приоритетнее цепочки)
ui:                           # последний выбор в интерфейсе (что меняете в окне — то и пишется; руками обычно не правят)
  direction: mine             # mine=я говорю | theirs=собеседник говорит | dual=в обе стороны одновременно
  chatbox: true               # флажок вывода: пузырь chatbox
  chatbox_text: translated    # что показывать в пузыре: translated=перевод (по умолчанию) | source=оригинал (распознанный ASR)
                              # вход в интерфейсе: во второй строке справа от chatbox кнопка «🌐 Пузырь: Перевод / 📝 Пузырь: Оригинал»
  overlay: true               # флажок вывода: экран на запястье
  desktop_overlay: true       # флажок вывода: субтитры на рабочем столе
```

### Микрофонный прокси: оригинал / перевод одним нажатием (включён по умолчанию)

Раньше, чтобы собеседник услышал перевод, приходилось вручную переключать микрофон в VRChat на
виртуальную звуковую карту, а когда она становилась не нужна — переключать обратно;
теперь программа сама занимает эту виртуальную звуковую карту, и в VRChat её достаточно
**выбрать один раз** (в Windows — ту, что вы установили, например `CABLE Input` / `VoiceMeeter Input`),
после чего переключать в главном окне:

- **Кнопка во второй строке главного окна** (справа от `Вывод озвучки`): `🎙 Оригинал` / `🗣 Перевод` —
  одним нажатием решает, «что идёт в виртуальную звуковую карту»: одно нажатие — и собеседник слышит
  ваш настоящий голос, ещё одно — перевод.
- **Когда кнопка доступна**: есть прокси **и** идёт перевод. Режим «Перевод» включается только после
  «Начать перевод»; **остановка перевода автоматически возвращает режим «Оригинал»** (последняя фраза
  перевода не остаётся в виртуальном микрофоне). Если виртуальная звуковая карта не установлена /
  не открывается — кнопка неактивна.
- **Перевод по умолчанию стартует в режиме «Перевод»**: если отмечен «Вывод озвучки» и прокси доступен,
  нажатие «Начать перевод» **автоматически** переключает в `🗣 Перевод` (самому нажимать переключатель
  больше не нужно); одно нажатие возвращает `🎙 Оригинал`. Если «Вывод озвучки» не отмечен или в направлении
  нет ветки «Я», переключения **не будет** — в этом случае режим «Перевод» был бы тишиной, а это хуже «Оригинала».
- **Прямой пропуск с самого запуска**: как только программа открылась, микрофон уже идёт в виртуальную
  звуковую карту (перевод для этого запускать не нужно) — говорить в VRChat можно в любой момент.
- **Флажок «Вывод озвучки» остаётся общим выключателем ветки перевода**: без него перевод в микрофон
  не идёт, и при нажатии «Перевод» появится сообщение, что «режим перевода будет беззвучным».
- **Одноразовое пояснение при первом реальном запуске**: при первом фактическом запуске прокси
  показывается разовое пояснение — он **постоянно занимает выходной поток виртуальной звуковой карты**;
  если устройство воспроизведения по умолчанию — та же карта, вы услышите собственный голос (эхо),
  а если это не нужно, снимите галочку в `Настройки → Мик-прокси` (карта освобождается сразу).
  После показа это записывается в конфиг и больше не показывается.
- **Выключение «Микрофонного прокси»** = возврат к прежнему поведению: виртуальная звуковая карта
  включается и выключается вместе с переводом, а переключения одним нажатием в главном окне нет.

Настройки находятся в `⚙ Настройки → Звук → Микрофонный прокси`, применяются сразу, перезапуск не нужен:

| Параметр | Диапазон | По умолчанию | Описание |
|---|---|---|---|
| Включение | флажок | вкл. | Выключение возвращает прежнее поведение |
| Буфер прямого сигнала (мс) | 60–500 | 150 | Задержка / устойчивость к разрывам в режиме «Оригинал». ⚠️ Не опускайте ниже 60 — один входной блок микрофона ~100 мс, и буфер меньше блока отрежет от каждого блока большую часть, звук сильно прерывается |
| Буфер перевода (мс) | 50–2000 | 300 | Джиттер-буфер режима «Перевод» (это и есть `output.audio.buffer_ms`) |

Соответствующие ключи `config.yaml`:

```yaml
output:
  audio:
    buffer_ms: 300               # буфер перевода (мс)
    proxy:
      enabled: true              # общий выключатель микрофонного прокси
      passthrough_buffer_ms: 150 # буфер прямого сигнала (мс), минимум 60
      hint_shown: false          # показывалось ли разовое пояснение (ведёт приложение)
```

Если виртуальную звуковую карту не установить / не открыть: кнопка **неактивна, нажать нельзя**,
а в строке состояния и в журнале остаётся по одной строке
(`Микрофонный прокси недоступен (виртуальная звуковая карта не открыта?); переключение Оригинал/Перевод отключено` /
`[proxy] 代理不可用 → 回到旧行为：译音输出由引擎自建（随翻译启停），主界面「原声/译音」切换已禁用`); chatbox / экран на запястье / субтитры на рабочем столе
**работают как обычно**, это их не затрагивает.

### Тонкая настройка экрана на запястье («⚙ Настройки → Экран на запястье», 14 ползунков, применяется на лету)

| Ползунок | Диапазон / шаг | Ползунок | Диапазон / шаг |
|---|---|---|---|
| Позиция X / Y / Z | −0.30 ~ 0.30 м, 0.005 | Размер | 0.05 ~ 0.80 м, 0.01 |
| Наклон / Поворот / Крен | −180 ~ 180°, 1 | Изгиб | 0.0 ~ 0.50, 0.01 (доля полной окружности; 0.5 = 180°) |
| Прозрачность | 0.10 ~ 1.00, 0.05 | Размер перевода | 20 ~ 64, 1 |
| Размер оригинала | 14 ~ 48, 1 | Высота панели | 240 ~ 560 px, 10 |
| Непрозрачность фона | 0 ~ 255, 5 | Непрозрачность оригинала | 0 ~ 255, 5 |

Плюс список **привязки** (правая рука / левая рука / **внешний трекер** / перед шлемом) и **номер трекера** (0–7).
**Позиция и поворот хранятся отдельно для каждой привязки** (`overlay.offsets.<привязка>`): переключение
списка подгружает позу этой привязки, так что настройка одной не затирает другую (`overlay.offset` —
только **запасной** вариант для привязок, которые ещё не сохранены отдельно). Системы координат хвата
левой и правой руки зеркальны по X, поэтому для левой руки значения правой не подходят
(`rx` без изменений, `ry`/`rz` с обратным знаком, компонента `x` позиции — так же).
Изменения записываются на диск с задержкой 200 мс; **размер перевода / размер оригинала / высота панели /
непрозрачность фона / непрозрачность оригинала** вызывают однокадровую перерисовку текстуры,
остальные только заново применяют преобразование.
**Непрозрачность фона** — это полупрозрачная подложка (меньше = сильнее видно сцену, 255 = полностью непрозрачно);
**непрозрачность оригинала** влияет только на строку оригинала (хотите «подложка полупрозрачна, текст плотный» —
поставьте 255). Верхняя **прозрачность** — множитель **всего слоя** (гаснут и подложка, и текст),
та же семантика, что у `setOverlayAlpha` в SteamVR на Windows.

> Практический ориентир: размеры 42/30 и панель 320 px — это **2 раунда** диалога; 36/24 и 420 px — **3 раунда, 6 строк**.

### Субтитры на рабочем столе (окно субтитров, приклеенное к окну VRChat — шлем не нужен)

**Для игроков в настольном режиме ПК** (issue #11): включите «Субтитры на рабочем столе» — и появится
окно субтитров **без рамки, поверх всех окон и прозрачное для мыши**, показывающее последние строки
чата (собеседники слева, вы справа).

* **Привязка**: по умолчанию окно цепляется к **нижнему центру окна VRChat** и следует за ним
  (перемещение и смена разрешения). Если окно VRChat не найдено, оно переходит на фиксированные
  координаты и пишет одну строку в журнал.
* **Положение**: собственный вход настройки «Настройки → Субтитры на рабочем столе» → «Разрешить
  перетаскивание» → перетащите окно субтитров куда нужно → «Закрепить положение» (точка сброса пересчитывается в
  «какой якорь + какое смещение» и записывается в `config.yaml`, поэтому при движении окна VRChat
  субтитры остаются у той же стороны). Прозрачность для мыши включена по умолчанию (не мешает кликам
  в VRChat); для перетаскивания её нужно снять.
* **Размер / шрифт / прозрачность**: всё в том же «Настройки → Субтитры на рабочем столе» (ширина панели / высота панели / размер перевода / размер оригинала / прозрачность), применяется сразу, сохраняется после отпускания.
* **Настройка**: секция `desktop_overlay:` в `config.yaml` (`mode: latest` — режим «только последняя
  фраза», как в караоке). ⚠️ В этой секции **свой полный набор визуальных ключей**
  (шрифт / размер / цвета / число строк / показывать оригинал / размеры панели), и она
  **полностью независима от секции `overlay:` экрана на запястье** — панель на рабочем столе
  это пиксельная панель на экране (px), а экран на запястье — текстура в VR (метры), это вообще
  разные вещи. Изменение `overlay:` не тронет субтитры на рабочем столе, и наоборот.
* **Linux**: в **сессии Wayland** (niri / sway / Hyprland / KDE и другие композиторы с
  layer-shell) субтитры работают как **нативное окно-оверлей**: попиксельная прозрачность
  (настоящие скругления, полупрозрачная подложка), поверх всех окон, следование за окном игры,
  прозрачность для мыши на уровне протокола, сохранение перетаскивания — всё как в Windows.
  Сессии X11 (включая GNOME/Weston с XWayland) работают как **нативное ARGB-окно-оверлей**
  (попиксельная альфа + прозрачность для мыши через X Shape); для смешивания нужен композитор
  (picom и т. п.) — без него включается деградация на 1-битную маску формы (чёрной рамки нет;
  скругления становятся зубчатыми, подложка непрозрачной) с одной строкой в логе. `desktop_overlay.backend`
  принудительно выбирает путь (удобно при отладке отрисовки) — границы см. в разделе
  «Субтитры на рабочем столе» файла [GUIDE.linux.md](GUIDE.linux.md).

> ⚠️ VRChat должен быть в **оконном / безрамочном** режиме (Unity `Fullscreen mode = 3`, по умолчанию
> в VRChat). В монопольном полноэкранном режиме любое стороннее окно поверх будет перекрыто — это не
> баг программы.
> Посмотреть отрисовку офлайн: `python -m vlt.output.desktop_overlay --demo --out out/desktop_frames`.

### Комната для нескольких человек (субтитры друг друга)

**Для случаев «играем компанией, но голосовой канал занят языком местных игроков»**: несколько человек
**независимо** запускают свою копию программы и вводят **один и тот же код комнаты**, чтобы попасть
в одну комнату — тогда каждый на своём экране на запястье / субтитрах видит **что говорят остальные**.

* **Как включить**: `⚙ Настройки → Комната` → укажите **код комнаты** (8 символов, у всех должен
  совпадать; лень придумывать — нажмите «Сгенерировать» и продиктуйте код собеседнику) и **ник**
  (пусто = имя пользователя системы) → закройте настройки → в третьей строке главного окна нажмите
  **«Войти в комнату»**. После подключения кнопка станет **красно-коричневой «Отключиться»**,
  а справа появится `Статус: Подключено · N чел.`.
* **Чтобы говорить, сначала нажмите «Начать перевод»**: в комнате передаётся **распознанный оригинал
  вашей речи** (без перевода), а берётся он из микрофонной ветки — если перевод не запущен, вы только
  принимаете чужие сообщения, а свои отправить не можете. Направление должно включать «Я».
* **Код комнаты**: 8 символов Crockford Base32, из набора **убраны легко путаемые при чтении
  `I / L / O / U`**. Ручной ввод снисходителен: `I` и `L` считаются как `1`, `O` как `0`,
  дефисы и пробелы игнорируются. Чтобы попасть в ту же комнату, остальным нужен **тот же код**.
* **Передаётся только ваша речь**: ветка захвата звука игры (loopback) явно исключена —
  чужие слова через вас не переотправляются, поэтому петля не возникает.
* **Экран на запястье красит по человеку и показывает ник**: даже когда в комнате говорят
  несколько человек сразу, видно, кто говорит; в чате и субтитрах — то же самое.
* **Изменения действуют сразу**: код комнаты / ник записываются в `config.yaml` немедленно;
  при активном подключении комната подключается заново с новыми настройками.
* **Настройка**: секция `room:` в `config.yaml` (в интерфейсе доступны только код комнаты и ник,
  остальное правьте вручную)

  ```yaml
  room:
    enabled: true                      # после нажатия «Войти в комнату» станет true и запомнится при следующем запуске
    server_url: "wss://vlt-room.kcm-nixi.cn/ws"
    room_code: "TESTTEST"              # 8 символов, у всех должен совпадать
    nickname: ""                       # пусто = имя пользователя системы
    broadcast_source: true             # отправлять в комнату то, что говорите «Я»
    show_remote: true                  # показывать чужую речь на экране на запястье / в чате
  ```
* **Сервер**: Cloudflare Worker в `server/` (на каждую комнату — свой Durable Object), **переносит
  только текст**: не переводит, никуда не сохраняет, пустые комнаты освобождаются автоматически.
  Хотите свой — разверните по [server/README.md](../server/README.md) и направьте `server_url`
  на свой адрес.
* **В этой версии передаётся только текст, без звука**: интерфейс для обратной подачи TTS уже
  заложен, но в этой версии не открыт.

> ⚠️ Известное ограничение: **номер участника сервер генерирует случайно при каждом подключении**,
> поэтому «после переподключения у одного и того же человека тот же цвет» **не выполняется** —
> если человек отключится и подключится снова, на вашем экране он будет другого цвета.
> На практике узнавайте людей по **нику** (он стабилен).

## 7. Решение проблем

| Симптом | Причина / решение |
|---|---|
| В пузыре ничего нет | VRChat не запущен / OSC выключен / видимость чат-пузырей стоит Off. Если `--dry-run` показывает логи отправки, значит со стороны программы всё в порядке |
| `[loopback] ❌ no loopback device found` | VRChat ничего не воспроизводит либо вы **работаете внутри сеанса удалённого рабочего стола** (конечные точки WASAPI изолированы по сеансам — нужно быть в текущем сеансе физической машины) |
| Микрофон ничего не ловит | То же самое; сначала проверьте, какое устройство выбрано в списке в «⚙ Настройки» (когда перечисление пустое, строка состояния поясняет, что для удалённого сеанса это нормально). Поищите в журнале `[mic]`: «已回落到同名设备» означает, что конечную точку WASAPI этой звуковой карты открыть не удалось и программа сама переключилась на другой интерфейс с тем же именем (это нормально); настоящим сбоем является только «所有候选设备都打不开» |
| `Voice 'Chelsie' is not supported` | `session.voice` не задан. Оставьте `Tina` |
| `Invalid translation parameter` | В `session.update` нет поля `translation` (в коде это гарантировано; имейте в виду, если будете править) |
| `1007 Requests rate limit exceeded` | Достигнут лимит RPM 10. Подождите минуту; не перезапускайте часто (**каждое подключение WS считается одним запросом**) |
| Перевод застревает на половине фразы | Понижен порог резерва по тишине. `session.final_silence_s` должен быть больше 2.3 с; по умолчанию 3.0 |
| Финальная версия приходит через ~3s после того, как вы замолчали | Быстрое завершение выключено (`session.fast_final_silence_s: null`) или не срабатывает: признак — **уровень**; в шумной обстановке быстрый путь деградирует до 3.0s (консервативно, без преждевременных финалов) |
| `[overlay] ⚠️ SteamVR not running or unavailable` | Нормальная деградация: не будет только экрана на запястье, на chatbox это не влияет |
| Экрана на запястье не видно | Сначала убедитесь, что SteamVR запущен; затем настройте положение и размер в «Настройки → Экран на запястье»; если `--overlay-dry-run` даёт PNG, отрисовка в порядке |
| Экран на запястье исчезает через некоторое время | Встроено двухуровневое самовосстановление (3 сбоя подряд → пересоздание overlay → ещё 3 → жёсткий перезапуск соединения openvr → далее одна попытка на каждые 50). В журнале каждые 30 секунд есть строка `[overlay][diag] heartbeat: …` — «сколько прошло с последней успешной отправки / сколько было пересозданий» |
| Нет звука из вывода озвучки | ① должны быть включены оба переключателя (флажок вывода и на уровне направления); ② работает только для направления «Я»; ③ установлена ли виртуальная звуковая карта? Строка состояния и журнал прямо называют причину; ④ **на всё остальное это не влияет** |
| В интерфейсе «Начать перевод» ничего не делает | Сначала посмотрите вывод терминала — исключения в обратных вызовах asyncio печатают одну строку трассировки только в консоль, не в строку состояния (в exe смотрите самый свежий `.log` в `logs/`) |
| Непонятная ошибка | **«⚙ Настройки → Экспорт журналов»** — обезличивание автоматическое; отправьте архив разработчику |

├── credentials.py        Сохранение / удаление / маскирование API-ключа
├── devices.py            Перечисление аудиоустройств и «разбор имени обратно в индекс»

├── session/

└── output/
    ├── merger.py         Первая порция сразу → снимок каждые 2 с → финал в конце фразы
    ├── chatbox.py        OSC ,sTT + ведро токенов + очередь повторной отправки финала

    └── virtualmic.py     Возврат озвучки: ресемплинг 24k→48k + джиттер-буфер (отбрасывается целыми фразами, фразы не режутся)

server/                   Сервер комнаты (Cloudflare Worker + Durable Object, разворачивается отдельно)
scripts/                   Инструменты разведки и отладки (probe_* / osc_listen / verify_release / room_e2e_local)

tests/                    74 файлов, 575 тестовых функций (работают офлайн; CI выполняет их по

docs/                     Результаты измерений P0.5 / P1 / P2 (протокол, задержка, экран на запястье)

## 9. Разработка

### Запуск тестов

**pytest не используется** (его нет в зависимостях): каждый файл тестов — самостоятельный исполняемый скрипт, ровно такой же, как в CI:

```bat
:: все (по файлам, как в CI; вставляйте прямо в cmd — в .bat-файле замените %t на %%t)
for %t in (tests\test_*.py) do @.venv\Scripts\python.exe %t

:: один файл
.venv\Scripts\python.exe tests\test_virtualmic.py
```

Тесты **полностью офлайновые** (не нужны ни микрофон, ни VRChat, ни SteamVR, ни сеть): они покрывают разбор устройств,
выбор путей, переподключение, ротацию и обезличивание журналов, окно поддержки, самовосстановление экрана на запястье,
инварианты буфера озвучки, запись конфигурации с сохранением комментариев и многое другое.

Единственное исключение — `tests/test_engine.py`: он открывает настоящую сессию и **требует настроенного на этой машине API-ключа**;
в CI он явно пропускается (рабочий процесс печатает `::notice::` с объяснением — молчаливого пропуска нет).

Одной командой всё сразу (заодно с покрытием) можно прогнать встроенным раннером репозитория:

```bat
.venv\Scripts\python.exe scripts\run_tests.py             :: по файлам, автоматически пропускает test_engine.py
.venv\Scripts\python.exe scripts\run_tests.py --coverage  :: дополнительно печатает сводку покрытия (без порога)
.venv\Scripts\python.exe scripts\run_tests.py --only i18n  :: только тесты, в имени которых есть i18n
```

После правок кода заодно прогоните статическую проверку (в CI это **блокирующий** гейт):

```bat
.venv\Scripts\python.exe -m ruff check --select F,E9 .
```

### Сборка

```bat
build_exe.bat                                              :: сборка + последующая самопроверка
.venv\Scripts\python.exe scripts\build_exe.py --no-verify  :: только сборка
```

Результат `dist\VRChatLiveTranslate.exe`: PyInstaller, **один файл, без окна консоли**,
внутри `config.example.yaml` / `testdata` / `assets`, около 37 МБ.
По умолчанию после сборки один раз реально запускается `exe --self-test`; проход засчитывается, только если в журнале найден `GUI_SELFTEST_OK`.

### CI / релиз

- **CI** (`.github/workflows/ci.yml`, при push в main / PR / вручную):
  проверка синтаксиса → **статическая проверка (уровень `F,E9` ruff, блокирует)** → сканирование учётных данных → прогон всех офлайн-тестов по файлам
  (заодно накапливается покрытие, в конце печатается сводка, **без порога и без блокировки**) → затем отдельная проверка **конвейера сборки** (артефакт существует и весит ≥ 20 МБ)
- **Релиз** (`.github/workflows/release.yml`, запускается push-ем тега `v*`):
  сначала сверяет тег с `__version__` в `vlt/__init__.py` (несовпадение = жёсткий отказ) → сборка **exe и Linux AppImage** →
  создание Release с вложениями **exe**, **`VRChatLiveTranslate-x86_64.AppImage`** и `SHA256SUMS.txt` (контрольную сумму GitHub показывает рядом с файлом как `sha256:…`; файл нужен как переходная мера для клиентов до v0.2.0)
- **Хотите проверить скачанное самостоятельно**: `scripts/verify_release.py` скачивает артефакты релиза и сверяет их
  (SHA256, реальный запуск `--self-test`, строка версии, поиск строк новых функций в байткоде, попиксельное сравнение иконки):

  ```bat
  .venv\Scripts\python.exe scripts\verify_release.py v0.10.0 "MicProxy,toggle_voice_mode,chatbox_text,passthrough_buffer_ms,意大利语"
  ```

## 10. Известные ограничения

- Экран на запястье требует, чтобы **активным композитором был SteamVR**: с родным OpenXR-рантаймом производителя сторонние оверлеи на стороне ПК не отображаются
- На входе доступен **только один стереоканал сведённого звука игры**: отдельных каналов по говорящим не существует, поэтому при одновременной речи нескольких человек определение говорящего принципиально ненадёжно
- В пути WebSocket **нет эхоподавления и шумоподавления** → **наушники обязательны** (на колонках захватывается и голос собеседника, и одна и та же фраза распознаётся дважды)
- Перевод в обе стороны = две сессии WebSocket, и бюджет расходуется на обе
- **Набор текста с озвучкой — это два запроса: «перевод + TTS»** — текст появляется почти сразу, а звук ждёт синтеза TTS (на практике сквозная задержка ≈ 2.6 с),
  поэтому собеседник слышит его на секунду-другую позже, чем вы видите в пузыре; голос — синтезированный TTS (по умолчанию `Cherry`) и **не совпадает** с голосом реалтайм-модели в речевом пути.
  Условия те же, что и у третьего пути: включён «Вывод озвучки» и есть виртуальная звуковая карта, иначе шаг пропускается автоматически и остаётся только текст
- **Набор текста заменяет микрофон**: поэтому он доступен только когда направление включает «Я» и только после нажатия «Начать перевод»
- **В комнате передаётся «распознанный оригинал вашей речи», а не перевод**, и отправить его можно,
  только **сначала нажав «Начать перевод»**; остальные видят ваш оригинал (при разных языках
  интерфейса автоперевода не будет)
- **Цвет участника комнаты меняется после переподключения**: номер участника сервер генерирует
  случайно при каждом подключении, «тот же цвет после переподключения» не выполняется —
  узнавайте людей по нику
- **В chatbox попадает только перевод того, что сказали *вы***: перевод речи собеседника в пузырь chatbox не идёт — смотрите экран на запястье или область чата в интерфейсе
